## v2.6.4

Released September 7, 2026 · [GitHub release](https://github.com/Marve10s/Better-Fullstack/releases/tag/v2.6.4)

Hotfix release. Publishes `create-better-fullstack`, `create-bfs`, `@better-fullstack/types`, and `@better-fullstack/template-generator` at 2.6.4.

**Fixes for generated projects**

- **Redwood stays on React 18.** The dependency sync had moved the Redwood web template to React 19, which `@redwoodjs/web` 8.9 rejects through its exact `react@18.3.1` peers. Template-specific pins now hold those versions, and the `latest` and `beta` dependency channels leave them alone as well. (#425)
- **Ash 3.33 projects compile.** Ash 3.33.0 refuses to compile any resource until `config :ash, default_string_length_count` is set. Elixir projects using Ash now generate the installer default. (#425)
- **Vue apps with Vercel Analytics build under Vite 8.** The `@vercel/analytics/vue` wrapper imports from `vue-router` at module scope, which the rolldown build fails on when the optional peer is absent. The generated component now uses the framework-neutral `inject()`. (#425)
- **The CLI refreshes the Bun cache after a registry miss** instead of failing on the stale index. (#419)

**Changes since 2.6.3**

- **The first screen proves the stack.** The generated home page leads with the project name and stack, and its main panel is a database-backed task list: adding a task writes a row through the ORM and API layer, and it survives a reload. With Better Auth the panel sits behind the session guard and every procedure is scoped to the signed-in user. Covers Drizzle on SQLite, Postgres, and MySQL with tRPC and TanStack Router; other stacks show an honest fallback panel. (#419)
- **Generated web apps can expose WebMCP tools** through the new `--web-mcp` option, covered by the builder, history replay, and update paths. (#420)
- **MCP server isolates startup and enforces response schemas.** (40c2ba0)
- **Redwood GraphQL codegen dependency aligned** with the rest of the Redwood family. (#420)
- **Template dependency versions refreshed** for the patch and minor updates that passed the smoke lanes, and the repository's own toolchain updated. (#425, #426)

**Upgrading**

```bash
bunx create-better-fullstack@latest my-app
```

Existing projects can pull the template fixes with `bunx create-better-fullstack@latest update`.

## v2.6.0

Released August 18, 2026 · [GitHub release](https://github.com/Marve10s/Better-Fullstack/releases/tag/v2.6.0)

Better Fullstack has always been good at the first minute of a project. 2.6.0 is about every minute after it.

Until now the CLI could scaffold a stack and then had nothing more to say. This release adds a full lifecycle around an existing project - inspect it, plan a change, apply it, undo it - and it does that transactionally, so a half-applied change is no longer something you resolve by hand.

**Change a project after you've created it**

Two new commands, and two existing ones rebuilt on the same contract:

- **`status`** *(new)* - what your project is actually made of, read from its manifest rather than guessed.
- **`remove`** *(new)* - takes a stack part back out, behind a plan-then-apply gate.
- **`update`** - now plans a stack change, shows the diff, and applies it only against a review token from that exact plan.
- **`doctor`** - checks the project against the current templates and reports drift.

The transaction layer underneath them is new in this release, and every mutating path runs through it. If an apply fails partway, the project is restored rather than left in a mixed state, and `bfs_recover_project_transaction` can recover a run that was interrupted. Plans and applies are bound together by a token, so an apply cannot silently act on a stale plan - the thing you reviewed is the thing that runs.

The MCP server exposes the same lifecycle: `bfs_plan_part_removal`, `bfs_apply_part_removal`, and `bfs_recover_project_transaction` join the existing planning tools, so an agent gets the identical review-then-apply contract a human does.

**One command reaches every language**

The old hero command pinned `--backend none --frontend none --ecosystem react-native` to scaffold a mobile app. Beyond reading as a double negative, it quietly locked you out of Kotlin, Swift, and Flutter, which only existed inside the multi-ecosystem composer.

`--shape fullstack|frontend|backend|mobile` replaces that. You name what you're building, the CLI asks which language or platform fits, and it runs only the prompts that shape needs. Mobile routes React Native through the existing flow and Kotlin, Swift, and Flutter through stack-graph parts. .NET frontends now build through the stack graph too, instead of a special case.

**New stack options**

- **Vite+ workspace tooling** - the Vite+ toolchain as a first-class workspace option, with compatibility gates so it cannot be combined into a broken workspace.
- **Bot protection** - Vercel BotID and Cloudflare Turnstile, gated to the frontends and backends that can actually host them.
- **Vercel Analytics** - with a warning when the chosen frontend has no template for the provider, rather than generating something that does not run.

**Web**

The hero is now full-viewport and centres on a single copyable command, with a command bar for MCP clients beside it. The stack builder is grouped into sections with compact subsections and renders every category as option cards, which makes a 973-option surface navigable instead of a wall of pills. Returning visitors get a changelog widget. Five documentation pages that crashed are fixed, and the duplicates around them are gone.

**Fixes worth calling out**

Roughly a third of this release is hardening on the lifecycle work above - ownership and recovery, mutation boundaries, provenance-safe removal reviews, executable removal commands. Beyond that: `paraglide-js` is held at 2.23.2 because lix 0.12's native addon needs glibc 2.38+ and breaks Vercel's Amazon Linux image; the Storybook family is held at 8.x; Strapi client calls no longer pass Next fetch options they never supported; and the AdonisJS SigNoz tracing import gets the explicit extension `nodenext` requires.

**Better Fullstack v2.0.0 is live**

This is the multi-ecosystem release.

You can now build projects where each part of the app can use the ecosystem that fits it best.

TypeScript frontend.
Go, Rust, Python, Java, or Elixir backend.
Database layer.
Mobile app.
One project model.
One generated command.

**Multi-ecosystem support**

Better Fullstack is no longer limited to one ecosystem per project.

v2.0 adds a new stack graph model that understands project roles:

- Frontend
- Backend
- Database
- Mobile
- Shared tooling

That means the builder and CLI can now reason about a project as a real product made from multiple parts, instead of one flat list of options.

**New CLI part syntax**

The CLI can now parse and generate scoped project parts.

Example:

```bash
bun create better-fullstack my-app \
  --part frontend:typescript:react-vite \
  --part backend:go:gin \
  --database postgres
```

The important bit: choices now belong to the right role.

A backend option is a backend option.
A frontend library stays in the frontend flow.
Database choices stay tied to the database layer.

**Redesigned web builder**

The `/new` builder has been rebuilt around the new model.

The multi-ecosystem flow is now:

1. Frontend
2. Backend
3. Database
4. Mobile
5. Finalize

Each step focuses on one part of the project.

The final step handles general settings like package manager, AI docs, git, and version channel.

**Command preview while you build**

The builder now works better as a command composer.

You can keep choosing tools and still see the generated command update as you go.

Partial command during the flow.
Full command at the end.
Copy when ready.

**Better multi-ecosystem UX**

v2.0 also includes a lot of polish around the builder:

- Multi-Ecosystem mode is now a first-class toggle in the header
- New update modal for the 2.0 launch
- Cleaner step navigation
- Better role cards
- Tool icons in the right places
- Less noise in the Finalize step
- Compatibility fixes so TypeScript-only libraries do not appear where they should not

**Generator support**

The template generator now understands stack graph parts across the main ecosystem handlers.

This release wires the foundation through:

- TypeScript
- Go
- Rust
- Python
- Java
- Elixir
- Database templates

Not every possible combination is finished yet, but the base is now in place.

This is what lets future ecosystem combinations grow without bolting everything onto the old flat config.

**Validation and compatibility fixes**

A lot of this release is about making the new model behave correctly.

Fixed and improved:

- Scoped backend validation
- Go auth command roundtrips
- Web command roundtrips
- Reproducible CLI commands
- Frontend-only TypeScript options showing in the wrong step
- TypeScript defaults leaking into non-TypeScript stacks
- Builder CI and Playwright coverage around the new flow

**Published packages**

**Why 2.0**

This is a foundation release.

Better Fullstack is becoming a builder for real full-stack systems, not just single-ecosystem starter apps.

**What's New in v1.7.1**

This release significantly expands the tools and libraries you can pick when scaffolding a project, refreshes generated app dependencies, and fixes a handful of template issues that were breaking new builds.

**At a Glance**

- **More choices**: dozens of new options across UI libraries, icons, caching, email, search, observability, feature flags, and language-specific frameworks
- **Broader language coverage**: Python, Rust, Go, and Java now match TypeScript more closely in feature parity
- **Up-to-date dependencies**: generated apps ship with refreshed package versions
- **Important fixes**: TinaCMS and Supabase Auth templates now build cleanly on the latest Next.js and TypeScript

**New Frontend Options**

- **UI libraries**: MUI and Ant Design are now selectable for React projects
- **shadcn/ui**: two new style presets - Luma and Sera
- **Icons**: pick Heroicons or React Icons when using shadcn
- **Cleaner React templates** for Next.js, React Router, React Vite, TanStack Router, and TanStack Start

**Python Gets a Major Upgrade**

- **APIs**: choose Django REST Framework or Django Ninja
- **GraphQL**: scaffold a project with Ariadne
- **AI & search**: built-in Haystack integration
- **Task queues**: pick RQ, Dramatiq, or Huey
- **Type checking**: mypy or Pyright preconfigured
- **Plus**: ready-to-go caching, email, observability, and search modules

**Rust Catches Up**

New libraries you can include out of the box:

- **Utilities**: uuid, Chrono, Reqwest, config, DashMap, parking_lot, Secrecy, Tokio Util
- **API docs**: utoipa
- **Testing**: Proptest and Insta
- **Services**: email, Meilisearch search, Sentry-style observability, and Upstash Redis caching

**Go Catches Up**

- **CLI framework**: urfave/cli
- **Logging**: Logrus
- **Services**: Redis caching, Resend email, Sentry observability, and Meilisearch search

**Java Catches Up**

- **New framework**: Quarkus joins Spring Boot as a Java option
- **New libraries**: Resilience4j, Spring WebFlux, Spring Batch, Spring Kafka, Spring Mail, Spring Boot DevTools, Micrometer Prometheus, and Thymeleaf
- **Services**: caching, search, and email scaffolding included

**Cross-Ecosystem Services**

These work across multiple languages now:

- **Feature flags**: LaunchDarkly, Flagsmith, and Unleash
- **Caching, email, observability, and search**: expanded support and validation across every supported ecosystem
- **Email**: Plunk templates refreshed
- **Job queues**: worker templates updated

**Web Builder**

- Updated option catalog, tech icons, and resource links - all 405 builder options were validated
- New presets and saved-stack panels
- v1.7.1 changelog entry added to the in-app widget

**Fixes**

- **TinaCMS**: visual editing helpers now type-check correctly; TinaCMS + Next.js builds compile on the current TypeScript
- **Supabase Auth**: no longer crashes during Next.js prerender - the browser client now initializes lazily
- **Accessibility**: replaced a generic `role="region"` with `motion.section` to satisfy lint rules

**Dependency Refresh**

Generated app dependencies are bumped across frontend, backend, and language-specific manifests. A few pins are intentionally kept (e.g. `lint-staged@^16.4.0`) to preserve Node 20 compatibility.

**Pull Requests**

- #188 Expand ecosystem tool options
- #189 Update dependency versions
- #190 Update codebase dependencies
