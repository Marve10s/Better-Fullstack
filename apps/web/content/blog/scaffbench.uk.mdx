Агенти кодування дуже добре вміють писати код і напрочуд погано *запускають* проекти. Попросіть одного
створіть монорепо повного стеку продуктивного рівня, і воно із задоволенням витратить десять хвилин на написання від руки
маніфести, файли блокування та конфігурації — і результат часто не створюється.

ScaffBench вимірює саме це: агент у порожньому робочому просторі, специфікація проекту та хард
запитання наприкінці — **чи згенерований проект встановлюється та збирається?** Ми запустили ті самі специфікації
через три шляхи створення, щоб виділити, наскільки інструменти допомагають:

- **MCP** — агент використовує сервер Better-Fullstack MCP для планування та розробки проекту.
- **Згадка BF** — немає MCP; підказка вказує агенту на Better-Fullstack CLI і документи, і це
  створює саму команду `create`.
- **Prompt** — Better-Fullstack взагалі відсутній; агент вручну пише кожен файл з нуля.

Ми двічі запустили повний пакет на двох різних агентах CLI: **OpenAI Codex CLI** з трьома GPT
моделі (10 червня) і **Claude Code** з трьома моделями Claude (12 червня) — всього 72 прогони. Те саме
специфікації, ті самі підказки, та сама перевірка. Потім ми навмисно додали [легку третю розгортку](#the-light-sweep-gemini-kilo-and-opencode)
— ще дев’ять моделей у **Gemini CLI**, **Kilo** і **opencode**, лише в найлегшій специфікації —
довівши загальну кількість до 102 серій і п'ятнадцяти моделей.

## Результати заголовків

Заголовні цифри взяті з аналізу коду Claude — 36 прогонів: три моделі (Fable 5, Opus 4.8,
Сонет 4.6) × три шляхи створення × чотири характеристики проекту. Та сама машина, та ж упряж, ті ж підказки
окрім інструкцій щодо режиму створення. [GPT sweep](#gpt-models-on-codex-cli) показує
та сама структура, про що повідомляється окремо нижче.

| Шлях створення | Середній час | Середній час | Сер. вихідні токени | Будує проходження |
| --- | ---: | ---: | ---: | ---: |
| MCP | 113,4с | 85,9с | 5,553 | 12/12 (100%) |
| Згадка BF | 219,6с | 172,1с | 11,060 | 9/9 (100%)* |
| Підкажіть | 516,2с | 424,0с | 25,859 | 9/12 (75%) |

\* Три запуски зі згадуванням BF виключено зі знаменника, оскільки вони не підійшли до шаблону
помилка генератора на нашому боці, а не на тому, що зробив агент — див. [політику підрахунку балів](#what-counts-as-a-failure).

Визначилися три речі:

1. **MCP в середньому на ~4,6× швидше, ніж лише підказка** (і ~4,9× на медіанах), із ~4,7× менше
   вихідні жетони. Агент надсилає конфігурацію, а не код.
2. **Кожний запуск MCP пройшов перевірку** для кожної моделі. Запуски лише підказки перевищили 75% — досягнуто два запуски
   15-хвилинний тайм-аут і один створив монорепо, яке не було зібрано.
3. **Інструменти стискають відмінності моделей.** На шляху MCP навіть найменша модель відповідала
   прикордонні моделі зі 100% проходженням — це сталося швидше та дешевше.

## Методологія

### Три шляхи творення

Кожен запуск починається в порожньому каталозі з тим самим базовим запитом:

```text
You are running in an empty benchmark workspace:
{run_dir}

Create exactly one project directory named `{project_name}`.
Do not ask questions. Do not start a dev server. Do not write outside the
current working directory.
At the end, report the commands you ran and any errors you hit.

Benchmark target: {spec_title}
Requirements:
{spec_requirements}
```

Єдиною відмінністю між шляхами є інструкція режиму створення, додана до цього підказки.
Запускам лише підказок явно заборонено торкатися будь-чого нашого:

```text
Creation mode: prompt-only.
Do not use the Better-Fullstack MCP server, Better-Fullstack CLI,
Better-Fullstack website, or files from the Better-Fullstack repository.
Create the project from scratch by writing the files and manifests needed
for a runnable starter.
```

MCP виконується навпаки:

```text
Creation mode: Better-Fullstack MCP.
Use the Better-Fullstack MCP tools, starting with bfs_get_guidance. Then use
schema/compatibility/plan as needed and call bfs_create_project to create
the project.
```

І BF-mention запускається між ними — немає інструментів MCP, але підказка називає CLI, а README —
агент може читати перед тим, як створити неінтерактивну команду `create`.

### Чотири специфікації проекту

Специфікації навмисно поширені з «проекту вихідного дня» на «стек, який би сперечалася справжня команда
приблизно на тиждень":

| спец | Що він вимагає |
| --- | --- |
| `light-ts` | React + Vite, Hono на Bun, tRPC, SQLite + Drizzle, Tailwind + DaisyUI, Pino, Vitest, Biome — без авторизації, без платежів |
| `heavy-ts` | Next.js **та** додаток Expo/React Native, Hono на Bun, oRPC, PostgreSQL + Drizzle, Better Auth, Stripe, Resend, UploadThing, Effect, TanStack Store/Form/Query, Valibot, Vitest + Playwright, Vercel AI SDK, Socket.IO, Inngest, Framer Motion, OpenTelemetry, PostHog, Umami, Sanity, Upstash Redis, Algolia, S3, shadcn/ui, Turborepo, MSW, Storybook, PWA, Docker створення |
| `python-ai` | FastAPI, SQLModel, PostgreSQL, Pydantic, JWT auth, Celery, Strawberry GraphQL, LangChain + OpenAI SDK + LangGraph + CrewAI, Ruff |
| `multi-ecosystem` | TypeScript Next.js інтерфейс, Python FastAPI бекенд (SQLModel/Pydantic/LangChain/Celery), Go Служба Gin (GORM, gRPC, Cobra, Zap), спільна PostgreSQL |

`heavy-ts` — стрес-тест. Це також місце, де всі цікаві помилки в цьому тесті
сталося.

### Упряж

Дві розгортки, одна конструкція ременя:

- **Claude sweep:** Claude Код у безголовому режимі (`claude -p`), потік подій JSON, захоплений за
  бігти. Моделі: `claude-fable-5`, `claude-opus-4-8`, `claude-sonnet-4-6`, міркування за замовчуванням.
- **Очистка GPT:** OpenAI Codex CLI (`codex exec`), потік подій JSON, що фіксується за виконання. Моделі:
  `gpt-5.3-codex-spark` (велике зусилля), `gpt-5.4` (середнє), `gpt-5.5` (середнє).
- **Ізоляція:** кожен запуск отримує свіжий порожній робочий простір; Запуски MCP отримують сувору конфігурацію MCP лише з
  приєднано сервер Better-Fullstack.
- **Тайм-аут:** 900 секунд на пробіжку. Тайм-аут вважається невдачею агента.
- **Показники:** час настінного годинника, використання маркерів із власного звіту про використання агента, виклики інструменту MCP з
  потік подій. Вартість у доларах фіксується лише на Claude розгортці — наш джгут Codex не
  звіт про виміряну вартість.

Одна важлива асиметрія: розгортка GPT запущена на два дні раніше, проти генератора *перед*
виправлено помилки шаблону, які він виявив. Ось чому наведені нижче виключення генератора помилок потрапляють у GPT
результати важчі — і чому два розгортки не слід порівнювати один до одного за показниками проходження.

### Що вважається проходженням

Перевірка виконується *після* завершення роботи агента, проти того, що залишилося на диску:

- **TypeScript:** `bun install`, потім власний сценарій проекту `build` (або `check`/`lint`/`test`).
- **Python:** `compileall` в проекті, за винятком virtualenvs і пакетів постачальників.
- **Go:** `go mod download` і модуль повинні скомпілюватися.

Прогон вважається успішним, лише якщо кожна відповідна перевірка виходить із нуля. «Схоже на проект» не зараховується;
воно має будувати.

### Що вважається невдачею

<Callout kind="info">
  **Політика підрахунку балів:** збої, спричинені помилками в нашому власному генераторі шаблонів, виключаються з
  знаменник швидкості проходження — лише помилки, створені агентом, зараховуються до агента. Орієнтир
  Робота полягає в тому, щоб вимірювати агентів, а не відмивати наші помилки в їхній рахунок. Зворотний бік: ми публікуємо
  ці помилки генератора нижче, а не приховувати їх.
</Callout>

Під час перевірки Claude це мало значення рівно тричі: усі три моделі, на шляху згадування BF,
створив `heavy-ts` правильно через CLI — і всі три виявили ту саму помилку генератора в нашому
нативний (Expo) шаблон, де `app.json` встановлює режим веб-виведення, який працює лише з `expo-router`.
Агенти зробили все правильно; шаблон не вдалося створити. Ці три прогони виключені.
Помилки підказки (два тайм-аути, одна несправна рукописна збірка) є повністю створеними агентом і
розрахувати повністю.

У розгортці GPT, яка працювала проти генератора префіксів, це мало значення сім разів: `heavy-ts`
через MCP і через CLI не вдалося для всіх трьох моделей через виправлену помилку Storybook/Expo
ланцюжок, а також один мультиекосистемний каркас, чия служба Go поставляється без згенерованого `go.sum`.
Усі семеро виключені з тієї ж причини; власні помилки агентів GPT (три зламаних
рукописні збірки на підказковому шляху) враховуються повністю.

### Вартість

Розгортка Claude коштувала **$60,60** у вимірному використанні API (менше, ніж справжня кількість — два
звіт про закінчення часу очікування $0; джгут Codex взагалі не повідомляє про вартість). Читання розвороту є
цікавіше за все:

- Найдешевший проходження: **$0,12** — Sonnet 4.6 проходить `light-ts` через CLI за 21 секунду.
- Найдорожчі проходження: **$3,50–$4,21** — Рукописні проекти Fable 5 на швидкому шляху.
- Для Sonnet шлях підказки коштував приблизно в 5 разів його шлях MCP ($7,11 проти $1,47) і був у ~6,6 разів повільнішим за
  *низький* прохідний бал.

Шаблон дотримується всіх трьох моделей: чим більшу частину проекту має створити агент
тим більше ви платите за менш надійний результат.

Що розгортка GPT додає до картини:

- **Структура не залежить від постачальника.** Для кожної моделі GPT MCP є найшвидшим шляхом і
  prompt-only є найдорожчим серед вихідних токенів — такої самої форми, як результати Claude, на
  моделі інших постачальників *та* інший агент CLI.
- **Spark створений для швидкості, і це видно.** GPT-5.3 Codex Spark становив у середньому 32 секунди на MCP
  scaffold — найшвидші клітини в усьому бенчмарку — але на швидкому шляху його швидкість досягла
  Ціна надійності: він писав проекти вручну менш ніж за хвилину, і створено лише половину з них.
- **GPT-5.5 — це викид підказки.** Це була єдина модель в обох циклах, яка проходила *кожен*
  специфікація лише підказок, включаючи `heavy-ts` — на 542 секундах і 28 тисяч вихідних маркерів для цього одного запуску,
  проти 108 секунд до MCP.
- **Моделі GPT більше покладаються на інструменти.** Запуски Codex здійснили 10–34 виклики MCP на каркас порівняно з
  Claude 3–10, повторна перевірка сумісності та повторне планування частіше — з тим самим кінцевим результатом.

Застереження, яке варто повторити: дві перевірки проводилися різними агентами, у різні дні та
різні версії генератора. Порівняння шляхів у межах розгортки є експериментом; порівняння постачальників
поперек розгорток немає.

## Легка розгортка: Gemini, Kilo та відкритий код

Повний пакет коштує реальних грошей і реального ліміту бюджету, тому ми запустили наступну партію моделей
навмисно полегшена версія: **одна специфікація (`light-ts`) × три шляхи створення × один запуск на комірку**.
Дев'ять моделей у ще трьох агентах CLI, усі 12 червня:

- **Gemini CLI** — Gemini 3.1 Pro (остання версія Google і стандартна версія CLI).
- **відкритий код** (підписка Go) — Kimi K2.6, GLM-5.1, MiniMax M3, Qwen3.7 Max, DeepSeek-V4 Pro:
  поточний флагманський рівень відкритих ваг.
- **Kilo CLI** (безкоштовний рівень моделі) — Step-3.7 Flash, Laguna m.1, Nex N2-Pro.

Ті самі підказки, той самий 900-секундний бюджет, та сама перевірка, що й основні розгортки. Підрахунок балів відповідає
критерій заголовка — чи проект **встановлює та збирає** — тому помилки лише з ворсом не враховуються
проти запуску (суворі журнали знаходяться в артефактах запуску). Gemini отримав друге, випадкове повторення
усі три шляхи, які ми зберегли як вільну вибірку дисперсії: загалом 30 прогонів. (Десята модель,
Nemotron-3 Ultra на безкоштовному рівні Kilo виключено — кінцева точка була надто повільною, щоб керувати агентом

Що додає світлова розгортка:

- **Допоміжні шляхи були 18-за-18.** Кожна модель пройшла згадування як MCP, так і BF. Це включає в себе
  Крок 3.7 Flash — маленька, швидка, безкоштовна модель — створення правильного монорепо повного стека в 16
  секунд і 640 вихідних токенів через шлях згадування BF. Структура, яку ми бачили на Claude та GPT
  не є явищем прикордонної моделі; інструменти повністю вирівнюють ігрове поле.
- **Тільки підказка – це те, де поле розділяється.** Три з дев’яти моделей відправили зламані проекти, кожна в
  інструктивний спосіб: Крок 3.7 Flash закріпив `pino-http` до версії, яка не існує (інсталюйте
  не вдалося); MiniMax M3 назвав процедуру tRPC `useContext`, що стикається з вбудованим клієнтом tRPC
  метод (не вдалося перевірити тип); Nex N2-Pro написав імпорт, який не вирішується (не вдалося зведення).
  Жоден із цих режимів збою не існує на допоміжних шляхах, оскільки агент ніколи не пише a від руки
  маніфест.
- **Економічні показники тримаються на третьому, четвертому та п’ятому джгутах.** Кожна допоміжна пробіжка завершувалася під
  3k вихідних токенів. Кожен запуск лише підказки коштував 8–36 тис. — MiniMax M3 36 тис. — найдорожчий
  єдиний запуск у ScaffBench поки що для проекту, який не збирався.
- **Gemini 3.1 Pro чудово справляється з цим завданням.** Найшвидша клітинка згадування BF з усього тесту
  (26,7 секунди, 863 маркери), чотири виклики підручника MCP і одна з небагатьох моделей, які пройшли
  лише підказка. Його повторний зразок також є корисною перевіркою чесності: перший запуск підказки не вдався Biome
  ворсинки, другий пройшов чисто — одноразові осередки спрямовані, не остаточні.

Застереження щодо світлової розгортки: один запуск на клітинку та 25 запусків виконуються одночасно, тому настінний годинник
часи перенесення суперечливого шуму (пробіг згадування BF Gemini виміряно 27 секунд соло та 50 секунд паралельно
партія — однаковий результат, інший трафік). Розглядайте структуру шляху та проходження/відмову як сигнал, точно
секунд як приблизний.

## Якісний аналіз

### MCP підтримує роботу агентів

MCP виконується конвергентно в одній послідовності інструментів: `bfs_get_guidance` → перевірка сумісності → план →
`bfs_create_project`, від 3 до 10 викликів за запуск (специфікація мультиекосистеми потребувала найбільше
ітерації для встановлення дійсного стека). Вихід залишається малим, оскільки робота агента згортається
*вибір конфігурації* — запис файлів виконується генератором детерміновано. це так
також чому показники проходження не знижуються в міру зростання специфікації: `heavy-ts` до MCP передано для кожного
модель.

### Оперативні агенти потонуть у важких специфікаціях

На швидкому шляху `heavy-ts` переміг майже всіх. Байка 5 і Опус 4.8 все ще писалися
файлів після 15-хвилинного тайм-ауту. Sonnet 4.6 закінчив монорепо з 90 файлів за 767 секунд — і це
не побудував. GPT-5.3 Codex Spark перейшов до рукописного проекту за 68 секунд, але не
будувати або. Єдиним винятком для обох перевірок був GPT-5.5, який проходив через `heavy-ts`
підказка лише за 542 секунди та пройдено. Специфікації запальнички здебільшого проходили лише за запитом, але через хвилини
настінного годинника та 10–37 тисяч вихідних жетонів кожен. Написати стартер від руки - це щось передове в моделях
*може* зробити; це просто найповільніший, найдорожчий і найменш надійний спосіб його отримати.

### Бенчмарк перевірив наші власні шаблони

Найкорисніші невдачі були наші. Перевірка кожного створеного проекту виявилася **шестирівневою
помилки шаблону** в нашому генераторі, більшість з яких ховається за єдиним симптомом «Помилка створення збірки оповідань» на
`heavy-ts`. Перевірка GPT вразила їх першими — вісім із дев’яти збірок `heavy-ts` не вдалися, шість
їх у цьому ланцюжку генераторів — і розгортка Claude через два дні підтвердила, які виправлення відбулися:

1. Шаблони Storybook протестували інтерфейс за допомогою перевірки рівності, але `frontend` — це масив.
2. Невідповідність шляху до пакета бази даних залишила пакет БД без залежностей у режимі графічної частини.
3. `expo-network` був відсутній у рідному варіанті шаблону.
4. Пакунки фреймворку Storybook 8 не реекспортують типи `Meta`/`StoryObj` — імпорт потрібно було перемістити до
   пакети візуалізації.
5. `@better-auth/expo` потребує чіткого встановлення чотирьох однорангових залежностей Expo.
6. Власний `app.json` встановлює статичний режим веб-виведення, який працює лише з `expo-router` — це
   все ще відкрито, і це помилка, що стоїть за трьома виключеними запусками згадки BF.

П’ять із шести було виправлено та доставлено у `create-better-fullstack` 2.0.2 до публікації цього допису
поза. Проведення власного продукту через контрольний тест агента виявляється надзвичайно ефективним методом контролю якості
пропуск.

### Модель характеру

Sonnet 4.6 був найшвидшим і найдешевшим на всіх шляхах, і з інструментами він нічого не поступався
надійність. Fable 5 була найбільш продуманою — найбільша кількість жетонів, найдовші пробіги та на
швидкий шлях, що ретельності все ще недостатньо, щоб подолати тайм-аут на `heavy-ts`. Опус 4.8 сб
надійно між ними. Рейтинг ніколи не змінювався; *розрив* зробив. Інструменти чудові
еквалайзер: на MCP різниця між найкращою та найгіршою моделлю становила 102 секунди; підказка-тільки так і було
різні хвилини та, двічі, настінний годинник на стелі.

## Обмеження

- **Один запуск на клітинку.** 102 запуски достатньо, щоб побачити структуру, а не встановлювати довірчі інтервали
  на ньому. Час скаффолду також змінюється залежно від навантаження API — і паралельна партія легкої розгортки додає
  конфліктний шум на вершині (власне повторення Gemini показало як 2-кратний розкид часу, так і lint-fail/pass
  перемикатися між ідентичними прогонами).
- **Очищення не є прямими.** Для запуску GPT використовувався інший агент CLI (Codex), інший
  параметри міркування-зусиль, попередня версія генератора та відсутність вартості звіту; світло
  sweep охоплює одну специфікацію на трьох наступних CLI. Порівняння траєкторії в межах розгортки є надійними;
  Рейтинг моделей між виробниками не є тим, що вимірює цей тест.
- **Ми порівняли наш власний інструмент.** Система, підказки та перевірка є загальнодоступними за духом —
  підказки та політику наведено вище, а повну таблицю для кожного циклу можна знайти в додатку. Лікувати
  порівняння між шляхами (інструменти та відсутність інструментів) як знахідка, а не твердження про інше
  риштувальники.
- **Збірки, а не функції.** Перевірка підтверджує, що проект встановлюється та збирається, а не автентифікація
  поток працює або вебхук Stripe підключено правильно. Прохідний проект, який містить лише підказки, все ще може бути
  бракує більше специфікації, ніж згенерованої.
- **Заниження вартості тайм-ауту.** Запуски, припинені на 900 с, повідомляють про вартість 0 доларів США, що втішить підказку
  підсумки шляху.
