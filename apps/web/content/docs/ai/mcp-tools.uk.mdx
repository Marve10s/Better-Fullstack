Сервер MCP надає структуровані інструменти для агентів. Використовуйте їх замість того, щоб просити агента вгадати прапорці CLI з прози або копіювати довгі команди вручну.

## Рекомендовані робочі процеси

### Новий проект

1. `bfs_get_guidance`
2. `bfs_get_schema`
3. `bfs_check_compatibility`
4. `bfs_plan_project`
5. `bfs_create_project`

### Існуючий проект

1. `bfs_get_guidance`
2. `bfs_plan_addition`
3. `bfs_add_feature`

<Callout kind="warn" title="Mutation behavior">
`bfs_plan_project` лише для сухого запуску. `bfs_create_project` записує новий проект на диск. `bfs_add_feature` змінює існуючий проект. Створення проекту MCP та додавання функцій не встановлюють залежності.
</Callout>

<Callout kind="info" title="Graph metadata">
Інструменти планування, створення та додавання проекту включають `graphSummary`, `effectiveStack` та `stackPartSpecs`, щоб агенти могли перевіряти те саме подання стека, отримане на основі графа, яке зберігається `bts.jsonc`.
</Callout>

## Довідник інструменту

### `bfs_get_guidance`

| Поле | Подробиці |
| --- | --- |
| призначення | Повертає правила робочого процесу, семантику полів, правила неоднозначності та критичні обмеження. |
| Коли дзвонити | По-перше, перед іншими інструментами Better Fullstack MCP. |
| Записує файли | немає |
| Необхідні вхідні дані | Жодного. |
| Додаткові входи | Жодного. |
| Вихід | Інструкції з JSON, що охоплюють рекомендований порядок інструментів, поля масиву, правила екосистеми та приклади. |

```json
{}
```

### `bfs_get_schema`

| Поле | Подробиці |
| --- | --- |
| призначення | Повертає дійсні значення параметрів для однієї категорії або всіх категорій. |
| Коли дзвонити | Перед плануванням стека, особливо коли користувач назвав технології неформально. |
| Записує файли | немає |
| Необхідні вхідні дані | Жодного. |
| Додаткові входи | `category`, `ecosystem`. |
| Вихід | Дані схеми/параметрів JSON, відфільтровані за категоріями чи екосистемами. |

```json
{
  "category": "database",
  "ecosystem": "typescript"
}
```

### `bfs_check_compatibility`

| Поле | Подробиці |
| --- | --- |
| призначення | Перевіряє комбінацію стеків і повертає скориговані виділення з попередженнями. |
| Коли дзвонити | Перед `bfs_plan_project` або `bfs_create_project`. |
| Записує файли | немає |
| Необхідні вхідні дані | `ecosystem`. |
| Додаткові входи | Інтерфейс, бекенд, час виконання, база даних, ORM, API, автентифікація, служби, UI/CSS, мобільні поля, аддони, приклади, менеджер пакетів, поля розгортання та поля, пов’язані з екосистемою. |
| Вихід | Аналіз сумісності JSON зі змінами, примітками та скоригованими даними стеку. |

```json
{
  "ecosystem": "typescript",
  "frontend": ["next"],
  "backend": "self",
  "runtime": "none",
  "database": "postgres",
  "orm": "drizzle",
  "api": "trpc"
}
```

### `bfs_plan_project`

| Поле | Подробиці |
| --- | --- |
| призначення | Створює проект у пам’яті та повертає підсумок дерева файлів. |
| Коли дзвонити | Після перевірки сумісності та перед записом файлів. |
| Записує файли | немає |
| Необхідні вхідні дані | Жодного, але рекомендовано `projectName` та `ecosystem`. |
| Додаткові входи | Повний вибір стека проекту. |
| Вихід | Позначка успіху JSON плюс згенерований підсумок файлів/каталогів, `graphSummary`, `effectiveStack` та `stackPartSpecs`. |

```json
{
  "projectName": "my-app",
  "ecosystem": "typescript",
  "frontend": ["tanstack-router"],
  "backend": "hono",
  "runtime": "bun",
  "database": "sqlite",
  "orm": "drizzle"
}
```

### `bfs_create_project`

| Поле | Подробиці |
| --- | --- |
| призначення | Записує новий згенерований проект на диск. |
| Коли дзвонити | Лише після успішного виконання `bfs_plan_project` і підтвердження користувача. |
| Записує файли | Так, створює каталог проекту та згенеровані файли. |
| Необхідні вхідні дані | `projectName`. |
| Додаткові входи | Повний вибір стека проекту. |
| Вихід | Позначка успіху JSON, каталог проекту, кількість файлів, метадані графіка, попередження надбудови та вказівки щодо команди встановлення. |

```json
{
  "projectName": "my-app",
  "ecosystem": "java",
  "javaWebFramework": "spring-boot",
  "javaBuildTool": "maven",
  "javaTestingLibraries": ["junit5"]
}
```

### `bfs_plan_addition`

| Поле | Подробиці |
| --- | --- |
| призначення | Читає `bts.jsonc` і перевіряє запропоновані доповнення для існуючого проекту. |
| Коли дзвонити | Перед зміною існуючого проекту за допомогою `bfs_add_feature`. |
| Записує файли | немає |
| Необхідні вхідні дані | `projectDir`. |
| Додаткові входи | `addons`, `webDeploy`, `serverDeploy`. |
| Вихід | Існуючий підсумок конфігурації, пропоновані доповнення, метадані графіків для обох, уже наявних додатків і попередження про сумісність. |

```json
{
  "projectDir": "/absolute/path/to/my-app",
  "addons": ["mcp", "skills"]
}
```

### `bfs_add_feature`

| Поле | Подробиці |
| --- | --- |
| призначення | Додає підтримувані аддони або параметри розгортання до існуючого проекту Better Fullstack. |
| Коли дзвонити | Після того, як `bfs_plan_addition` буде успішним і користувач схвалить. |
| Записує файли | Так, змінює існуючий проект. |
| Необхідні вхідні дані | `projectDir`. |
| Додаткові входи | `addons`, `webDeploy`, `serverDeploy`, `packageManager`. |
| Вихід | Результат JSON з обробника додавання, метадані графіка після оновлення та вказівки щодо встановлення, якщо доступні. |

```json
{
  "projectDir": "/absolute/path/to/my-app",
  "addons": ["biome"],
  "packageManager": "bun"
}
```

## Правила агента

- Розглядати `frontend`, `addons`, `examples`, `rustLibraries`, `pythonAi`, `javaLibraries` та `javaTestingLibraries` як масиви.
- Встановіть `ecosystem` перед вибором полів, пов’язаних із екосистемою.
- Віддайте перевагу `none`, коли користувач явно хоче вимкнути категорію.
- Створення проекту MCP наразі не відображає кожен прапор робочого процесу CLI. Наприклад, `aiDocs` використовує вбудовані параметри сервера за замовчуванням під час створення проекту.
- Не викликайте інструменти запису, доки користувач не схвалить план тестування чи додавання.
- Повідомте користувачеві, які команди встановлення/тестування виконувати після створення або додавання MCP, оскільки MCP не встановлює залежностей.
