The Better Fullstack MCP server lets agents scaffold and evolve projects through structured tool
calls instead of guessing CLI flags. It handles discovery, recommendations, compatibility checks,
dry-run previews, project creation, broad stack updates, and focused addon/deploy additions.

This page describes the Better Fullstack MCP server. The generated-project `mcp` addon is separate: it writes MCP client/server configuration into a scaffolded app and may run external setup commands.

<Callout kind="info" title="Protocol compatibility is automatic">
The stdio server negotiates both the 2025 MCP protocol family and MCP 2026-07-28 without a
client-specific flag or version pin. Modern clients use the stateless-core request model and
receive cache hints for tool and resource discovery, while older clients continue through the
legacy initialization flow.
</Callout>

## Choose your integration

All three paths use the same Better Fullstack generator. Choose the narrowest integration that
fits your agent:

| Integration                      | Includes                                              | Best for                                                                      |
| -------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| [Agent plugin](/docs/ai/plugin/) | MCP server and reusable skills in one portable bundle | Agents with plugin or marketplace support                                     |
| MCP server                       | Structured tools and resources over stdio             | MCP clients that need schema discovery, validation, planning, and safe writes |
| [Agent skill](/docs/ai/skills/)  | A lightweight CLI-driven workflow                     | Agents with shell access that do not need an MCP connection                   |

## Setup

Launch the server with the package manager you use:

<PMTabs
  npm="npx -y create-better-fullstack@latest mcp"
  pnpm="pnpm dlx create-better-fullstack@latest mcp"
  bun="bunx create-better-fullstack@latest mcp"
  yarn="yarn dlx create-better-fullstack@latest mcp"
/>

### Claude Code

```bash
claude mcp add --transport stdio better-fullstack -- npx -y create-better-fullstack@latest mcp
```

Use the same launcher table above if you prefer pnpm, Bun, or Yarn.

### Cursor

```json
{
  "mcpServers": {
    "better-fullstack": {
      "command": "npx",
      "args": ["-y", "create-better-fullstack@latest", "mcp"]
    }
  }
}
```

  "servers": {

## Tools

For full inputs, outputs, examples, and safe write behavior, see the [MCP tools reference](/docs/ai/mcp-tools/).

| Tool                      | Purpose                                                                     |
| ------------------------- | --------------------------------------------------------------------------- |
| `bfs_get_guidance`        | Returns workflow rules and field semantics. Call this first.                |
| `bfs_get_schema`          | Returns valid options for configuration categories.                         |
| `bfs_list_presets`        | Lists ready-made stacks and their canonical configuration.                  |
| `bfs_recommend_stack`     | Turns a product brief into a deterministic, validated stack recommendation. |
| `bfs_check_compatibility` | Validates a stack and returns adjusted selections with warnings.            |
| `bfs_plan_project`        | Dry-runs project generation in memory.                                      |
| `bfs_create_project`      | Writes a new project to disk.                                               |
| `bfs_plan_stack_update`   | Plans any supported scaffold-time stack change in an existing project.      |
| `bfs_apply_stack_update`  | Applies a reviewed stack update without overwriting edited generated files. |
| `bfs_plan_addition`       | Plans a focused addon or deploy-target addition.                            |
| `bfs_add_feature`         | Applies a focused addon or deploy-target addition.                          |

<Callout kind="info" title="Install behavior">
MCP project creation skips normal dependency installation to avoid long-running agent calls. If the generated project includes the `mcp` addon, that addon setup may still run external setup commands for MCP client configuration.
</Callout>

## Recommended tool order

For a new project:

1. `bfs_get_guidance`
2. Discover with `bfs_list_presets`, `bfs_recommend_stack`, or `bfs_get_schema`.
3. `bfs_check_compatibility`
4. `bfs_plan_project`
5. Ask for approval, then `bfs_create_project`.

For an existing project's stack:

1. `bfs_get_guidance`
2. `bfs_plan_stack_update`
3. Review conflicts, migration steps, and architecture changes.
4. Ask for approval, then `bfs_apply_stack_update` with the same requested fields.

Use `bfs_plan_addition` followed by `bfs_add_feature` only for the narrower addon and deploy-target
workflow.

## Key rules for agents

- Call `bfs_get_guidance` at the start of each workflow and `bfs_get_schema` instead of relying on
  remembered fields or values.
- Set `ecosystem` first, preserve arrays as arrays, and use `none` only where the schema permits it.
- Project planning, creation, and update responses include graph-backed stack metadata.
- A stack update requires an absolute `projectDir`. Plan and apply with the same requested fields.
- Architecture-changing updates do not migrate application data or schemas. Review `migrationSteps`
  and pass `acknowledgeArchitectureChange: true` only after explicit approval.
- Write tools do not install dependencies. Report the returned install command to the user.
