Сервер Better Fullstack MCP дозволяє агентам створювати проекти через структуровані виклики інструментів замість вгадування прапорів CLI. Він забезпечує пошук схеми, перевірку сумісності, попередній перегляд, створення проекту та додавання функцій.

На цій сторінці описано сервер Better Fullstack MCP. Надбудова створеного проекту `mcp` є окремою: вона записує конфігурацію клієнта/сервера MCP в програму зі скаффолдом і може запускати зовнішні команди налаштування.

Щоб полегшити робочий процес агента, керований CLI, установіть [Better Fullstack навик агента](/docs/ai/skills/). Сервер навичок і MCP використовують той самий генератор; навик оптимізовано для швидкого скаффолдингу на основі прапорів, тоді як MCP оптимізовано для викликів структурованих інструментів.

## Налаштування

Запустіть сервер за допомогою менеджера пакетів, який ви використовуєте:

<PMTabs
  npm="npx -y create-better-fullstack@latest mcp"
  pnpm="pnpm dlx create-better-fullstack@latest mcp"
  bun="bunx create-better-fullstack@latest mcp"
  yarn="yarn dlx create-better-fullstack@latest mcp"
/>

### Claude Код

```bash
claude mcp add --transport stdio better-fullstack -- npx -y create-better-fullstack@latest mcp
```

Використовуйте ту саму таблицю запуску, наведену вище, якщо ви віддаєте перевагу pnpm, Bun або Yarn.

### Cursor

```json
{
  "mcpServers": {
    "better-fullstack": {
      "command": "npx",
      "args": ["-y", "create-better-fullstack@latest", "mcp"]
    }
  }
}
```

### VS Code

```json
{
  "servers": {
    "better-fullstack": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "create-better-fullstack@latest", "mcp"]
    }
  }
}
```

### Інші клієнти MCP

Використовуйте ту саму команду stdio з такими клієнтами, як Claude Desktop, Zed, Cursor, Codex, OpenCode, Gemini CLI, Goose або іншими MCP-сумісними інструментами.

| Менеджер пакетів | `command` | `args` |
| --- | --- | --- |
| npm | `npx` | `["-y", "create-better-fullstack@latest", "mcp"]` |
| pnpm | `pnpm` | `["dlx", "create-better-fullstack@latest", "mcp"]` |
| Bun | `bunx` | `["create-better-fullstack@latest", "mcp"]` |

## Інструменти

Повні вхідні дані, виходи, приклади та поведінку безпечного запису див. у [MCP довідці про інструменти](/docs/ai/mcp-tools/).

| Інструмент | призначення |
| --- | --- |
| `bfs_get_guidance` | Повертає правила робочого процесу та семантику поля. Спочатку зателефонуйте цьому. |
| `bfs_get_schema` | Повертає дійсні параметри для категорій конфігурації. |
| `bfs_check_compatibility` | Перевіряє стек і повертає скоригований вибір із попередженнями. |
| `bfs_plan_project` | Генерація проекту в пам'яті. |
| `bfs_create_project` | Записує новий проект на диск. |
| `bfs_plan_addition` | Перевіряє зміни додатків для існуючого проекту. |
| `bfs_add_feature` | Додає підтримувані аддони до існуючого проекту. |

<Callout kind="info" title="Install behavior">
Під час створення проекту MCP пропускається звичайна інсталяція залежностей, щоб уникнути тривалих викликів агента. Якщо згенерований проект включає аддон `mcp`, цей додаток налаштування все ще може запускати зовнішні команди налаштування для конфігурації клієнта MCP.
</Callout>

## Ресурси

Сервер надає ці ресурси MCP:

| Ресурс | Зміст |
| --- | --- |
| `docs://compatibility-rules` | Правила сумісності для комбінацій стеків. |
| `docs://stack-options` | Доступні варіанти технологій за категоріями. |
| `docs://getting-started` | Швидкі рецепти для підтримуваних екосистем. |

## Рекомендоване замовлення інструменту

Для нового проекту:

1. `bfs_get_guidance`
2. `bfs_get_schema`
3. `bfs_check_compatibility`
4. `bfs_plan_project`
5. `bfs_create_project`

Для існуючого проекту:

1. `bfs_plan_addition`
2. `bfs_add_feature`

## Основні правила для агентів

- `frontend` — це масив, який може містити кілька інтерфейсних цілей.
- `none` вимикає категорію.
- Спочатку встановіть `ecosystem`, щоб агент використовував правильну сімейство полів.
- Поля масиву включають `frontend`, `addons`, `examples`, `rustLibraries`, `pythonAi`, `javaLibraries` та `javaTestingLibraries`.
- Відповіді щодо планування, створення та додавання проекту включають `graphSummary`, `effectiveStack` та `stackPartSpecs` для подання стека, що підтримується графіком.
- Поточні схеми проекту MCP не розкривають `aiDocs` як поле створення; створення проекту використовує вбудовану поведінку сервера AI-doc.
- Завжди викликайте `bfs_check_compatibility` перед створенням проекту.

## Підказка агента

```text
Use Better Fullstack MCP. First call bfs_get_guidance to understand
the rules, then bfs_get_schema for the relevant categories, then
bfs_check_compatibility to validate the stack, then bfs_plan_project
for a dry-run. Only call bfs_create_project after the dry-run succeeds.
Skip normal dependency installation and tell me the exact commands to
install, test, and run the project.
```
