Better Fullstack gives coding agents four ways to reach the generator. They all run the same code, so pick the narrowest one your agent supports.

## Choose an integration

| Integration                 | Includes                                             | Best for                                                                  |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| [MCP server](/docs/ai/mcp/) | Structured tools and resources over stdio            | Clients that need schema lookup, validation, planning, and guarded writes |
| Agent plugin                | The MCP server and two skills in one portable bundle | Agents with plugin or marketplace support                                 |
| Agent skill                 | A CLI-driven scaffold workflow                       | Agents with shell access and no MCP connection                            |
| Explicit CLI flags          | Nothing to install                                   | Any agent that can run a command                                          |

## Preferred workflow

1. Choose the target ecosystem from the [Ecosystem reference](/docs/ecosystems/).
2. Drive the generator through the MCP server, the agent skill, or explicit CLI flags.
3. Validate compatibility before scaffolding.
4. Dry-run to inspect the file tree.
5. Scaffold with dependency installation disabled while an agent is driving.
6. Tell the user the exact install, test, and run commands.

## Generated AI docs

`--ai-docs` writes project-local context files that a coding agent reads inside the generated project:

| Value         | File generated |
| ------------- | -------------- |
|`claude-md`   |`CLAUDE.md`    |
|`agents-md`   |`AGENTS.md`    |
|`cursorrules` |`.cursorrules` |
|`none`        | No AI docs     |

Pass more than one value to write more than one file:

```npm
npm create better-fullstack@latest my-app -- --ai-docs claude-md agents-md
```

## CLI workflow

An agent with only shell access should pass explicit flags and switch off side effects:

```npm
npm create better-fullstack@latest my-app -- \
  --ecosystem typescript \
  --frontend next \
  --backend self \
  --runtime none \
  --database postgres \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --db-setup none \
  --ai-docs agents-md \
  --version-channel stable \
  --no-install \
  --no-git
```

<Callout kind="info" title="CLI rules for agents">
`--yes` accepts defaults and is incompatible with core stack flags. Explicit flags skip only the categories they cover. Pass`none` for optional categories you want disabled.
</Callout>

## Agent skill

The agent skill teaches an agent to use the CLI instead of hand-writing starter files. It maps the requested stack to graph parts, runs a dry-run, scaffolds without install or Git side effects, then reports the follow-up commands.

The skill lives in this repository at`.agents/skills/better-fullstack`. The repository holds other internal skills too, so install only`better-fullstack`:

<PMTabs
  npm="npx skills@latest add Marve10s/Better-Fullstack --skill better-fullstack --agent codex --global --yes"
  pnpm="pnpm dlx skills@latest add Marve10s/Better-Fullstack --skill better-fullstack --agent codex --global --yes"
  bun="bunx skills@latest add Marve10s/Better-Fullstack --skill better-fullstack --agent codex --global --yes"
  yarn="yarn dlx skills@latest add Marve10s/Better-Fullstack --skill better-fullstack --agent codex --global --yes"
/>

Pass several agents in one command:

```bash
bunx skills@latest add Marve10s/Better-Fullstack \
  --skill better-fullstack \
  --agent codex claude-code cursor github-copilot gemini-cli \
  --global \
  --yes
```

Omit`--global` for a project-local install, which records the skill version with the repository.

Invoke the skill by name:

```text
Use $better-fullstack to create a React + Vite app with Hono, SQLite, Drizzle, tRPC, Tailwind, DaisyUI, Pino, Vitest, and Biome.
```

Agents that match skills implicitly can also pick it up from a plain request to scaffold, plan, or extend a Better Fullstack project. Either way the skill maps the stack to flags, dry-runs it, runs the same command for real when the plan succeeds, keeps`--no-install` and`--no-git` on unless you ask otherwise, and reports the command it used along with any compatibility adjustment.

## Agent plugin

The plugin bundles the MCP server with two focused skills:

-`scaffold-project` plans and creates new Better Fullstack projects.
-`add-to-project` previews and applies supported additions to existing generated projects.

Use it when your agent supports plugin marketplaces and you want one install to cover both the server and the skills.

For Claude Code, add this repository as a marketplace and install from it:

```bash
claude plugin marketplace add Marve10s/Better-Fullstack
claude plugin install better-fullstack@better-fullstack
```

The interactive`/plugin` flow works too. Claude Code namespaces the bundled skills by plugin name, so they are`better-fullstack:scaffold-project` and`better-fullstack:add-to-project`.

For Codex, the repository ships a marketplace catalog at`.agents/plugins/marketplace.json` pointing at the shared bundle in`./plugin`. Install it through the Codex plugin marketplace flow with this repository as the source. The Codex manifest is`plugin/.codex-plugin/plugin.json` and the MCP server definition stays shared at`plugin/.mcp.json`.

The bundle also implements the open Agent Plugins 1.0 format. Its root`plugin.json` identifies the plugin,`skills/` holds the reusable skills, and`mcp.json` declares the stdio MCP server, so a compatible client can load the same package without a client-specific layout.

## MCP server

The MCP server exposes schema and preset discovery, deterministic recommendations, compatibility checks, dry-run previews, project creation, stack updates, and focused capability additions as structured tool calls. See the [MCP server guide](/docs/ai/mcp/) for setup and the full tool reference.

This is a different thing from the generated-project`mcp` capability. The server helps an agent create Better Fullstack projects. The capability writes MCP configuration inside a project you generated.
