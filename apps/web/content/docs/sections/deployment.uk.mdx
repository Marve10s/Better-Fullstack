---
title: Розгортання
description: Виберіть цілі розгортання Інтернету та сервера як один розділ стека.
---

Розгортання – це один розділ стека, а не окремий стовп документів. Він контролює, чи Better Fullstack випускає файли платформи під час створення проекту за допомогою `--web-deploy` і `--server-deploy`.

Використовуйте прапорці розгортання під час шаффолду, якщо потрібно, щоб згенеровані файли платформи відповідали вибраному інтерфейсу, серверній частині, середі виконання та макету робочої області.

## Прапори розгортання

| Прапор | Цінності |
| --- | --- |
| `--web-deploy` | `vercel` `cloudflare` `fly` `railway` `render` `netlify` `docker` `sst` `none` |
| `--server-deploy` | `vercel` `cloudflare` `fly` `railway` `render` `docker` `sst` `none` |

Варіанти розгортання перевіряються на сумісність зі стеком. Деякі фреймворки fullstack розгортаються через веб-програму, деякі серверні частини не потребують окремого розгортання сервера, а Convex або Encore керують власним шляхом до платформи.

## Цілі

| Цільова | Найкраще підходить | Примітки |
| --- | --- | --- |
| Docker | Самостійне розміщення, відтворювані робочі зображення та оркестровка локальних послуг. | Окремо від аддона `docker-compose`, який зосереджується на локальних службах. |
| Vercel | Підтримується розгортання React, Nuxt, SvelteKit, Solid і без сервера. | Інтерфейси Fullstack зазвичай розгортаються через веб-програму, а не на окремому сервері. |
| Cloudflare | Стеки робочого часу виконання та крайні сервери Hono. | Сумісність поширюється на середовища виконання Workers-сумісного сервера. |
| Fly.io | Хостинг додатків із підтримкою Docker з регіональним розміщенням і довготривалими послугами. | Good для постійних серверних процесів. |
| Railway | Хостинг додатків, підключених до Git, зі збірками на основі Dockerфайлів і керованими службами. | Налаштуйте змінні робочого середовища перед розгортанням. |
| Рендер | Хостинг додатків на основі Blueprint зі збірками на основі Dockerфайлів (`render.yaml` у корені репо). | Веб і сервер розгортаються як окремі служби Docker; встановити змінні env на інформаційній панелі Render. |
| Netlify | Статичні та SSR веб-інтерфейси (Next.js, Vite SPA, SvelteKit, Nuxt). | Мета лише для Інтернету; встановіть базовий каталог сайту на `apps/web`. |
| SST | Інфраструктура, орієнтована на AWS, як код для робочих процесів програми TypeScript. | Найкраще, коли ви хочете явно володіти ресурсами AWS. |

## Перед розгортанням

- Встановіть змінні робочого середовища для секретів авторизації, URL-адрес бази даних, ключів постачальника та URL-адрес загальнодоступних програм.
- Перед маршрутизацією трафіку запустіть міграцію бази даних щодо робочої бази даних.
- Переконайтеся, що згенерована конфігурація платформи відповідає програмі, яка має отримувати запити.
- Тримайте лише локальні контейнери служб, тестові облікові дані та згенеровані журнали поза межами контролю джерел.

## Додайте після риштування

Команда `add` може записувати позначки розгортання, але наразі вона спочатку обробляє аддони. Якщо новий аддон не вибрано, команди `add` лише для розгортання завершуються раніше. Надавайте перевагу вибору цілей розгортання під час `create`, доки не буде розширено потоки додавання лише для розгортання.
