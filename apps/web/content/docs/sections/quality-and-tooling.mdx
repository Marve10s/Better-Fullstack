Quality and tooling choices decide how the generated project is checked, documented, and maintained.

## Testing

TypeScript testing choices include Vitest, Playwright, Vitest plus Playwright, Jest, Cypress, or none.

Other ecosystems expose their native testing paths, such as Rust testing libraries, Python quality tools, Java testing libraries, Elixir ExUnit/Mox/Bypass/Wallaby choices, and mobile testing with Maestro or React Native Testing Library.

## Logging and observability

Logging and observability can be stack-specific. TypeScript has Pino, Winston, Evlog, OpenTelemetry, Sentry, and Grafana choices. Go and Rust have dedicated logging categories. Java and Elixir expose observability-related libraries through their ecosystem options.

## JavaScript toolchain

Choose one primary profile:

- **Modular** keeps the workspace runner, code-quality profile, and Git hooks independently selectable.
- **Vite+ (Beta)** provides the unified `vp` command for install, run, build, test, lint, format, and checks. It replaces separate runner, quality, and hook selections, while still using the chosen npm, pnpm, Yarn, or Bun package manager underneath.

Vite+ requires a TypeScript web application. Native-only and backend-only workspaces are rejected.

## Dedicated tooling sections

The builder and CLI keep distinct compatibility rules for workspace runners, code quality, Git hooks, static analysis, AI tooling, documentation apps, app platforms, testing support, data clients, frontend utilities, HTTP clients, code generation, developer environments, local containers, API gateways, CI, and backend utilities.

Examples include Biome or ESLint + Prettier as quality profiles; Lefthook or Husky as hook managers; Knip and Gitleaks for analysis; and Starlight or Fumadocs as documentation apps. These are not combined in an unrestricted add-on bag.

## Project workflow

Package manager, version channel, AI docs, Git initialization, install behavior, `--dry-run`, and `--verify` all belong to the workflow layer rather than the generated app runtime.
