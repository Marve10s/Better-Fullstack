Команда `create` записує новий проект із введеної конфігурації стека. Використовуйте його в інтерактивному режимі для дослідження або передайте прапорці, коли вам потрібна одна й та сама форма проекту кожного разу.

<PMTabs
  npm="npm створити better-fullstack@latest [назва-проекту] -- [прапорці]"
  pnpm="pnpm створити better-fullstack@latest [назва-проекту] [прапорці]"
  bun="bun create better-fullstack@latest [назва-проекту] [прапорці]"
  yarn="yarn create better-fullstack@latest [назва-проекту] [прапорці]"
/>

Для npm прапорці Better Fullstack йдуть після `--`. Згенеровані команди npm можуть використовувати `npx create-better-fullstack@latest`; який запускає ту саму точку входу пакета в неінтерактивній формі.

## Командні режими

| Режим | Форма команди | Використовуйте його, коли |
| --- | --- | --- |
| майстер | `[launcher] my-app` | Вам потрібні підказки та стандартні параметри. |
| За замовчуванням | `[launcher] my-app [flags] --yes` | Вам потрібен стандартний стек без підказок. |
| Сценарний | `[launcher] my-app [flags]` | Вам потрібен повторюваний результат. |
| Сухий хід | `[launcher] my-app [flags] --dry-run` | Ви хочете перевірити файли перед записом. |

## Оперативна поведінка

- Явні прапори пропускають лише категорії, які вони охоплюють.
- `--yes` приймає значення за замовчуванням і конфліктує з прапорами основного стеку, такими як `--frontend`, `--backend`, `--database`, `--orm`, `--auth` та `--api`.
- Використовуйте `none`, щоб вимкнути додаткові категорії, включаючи `--ai-docs none`.
- Використовуйте `--no-install` і `--no-git`, якщо ви хочете перевірити згенеровані файли перед виникненням побічних ефектів.
- `--verify` запускає згенеровані перевірки після скаффолдингу без запуску серверів розробників.

## Приклади

Створіть програму TypeScript з явними прапорцями:

```npm
npm create better-fullstack@latest my-app -- \
  --ecosystem typescript \
  --frontend tanstack-router \
  --backend hono \
  --runtime node \
  --database postgres \
  --orm drizzle \
  --db-setup none \
  --api orpc \
  --auth better-auth \
  --css-framework tailwind \
  --ui-library shadcn-ui \
  --ai none \
  --payments none \
  --email none \
  --examples none \
  --addons none \
  --ai-docs none \
  --version-channel stable \
  --no-install \
  --no-git
```

Створіть мультиекосистемний проект:

```npm
npm create better-fullstack@latest my-mixed-app -- \
  --part frontend:typescript:next \
  --part backend:go:gin \
  --part backend.orm:go:gorm \
  --part backend.auth:go:jwt \
  --part database:universal:postgres \
  --part mobile:react-native:native-bare \
  --addons turborepo docker-compose
```

## Сумісність

- CLI перевіряє сумісність стеку перед створенням.
- TypeScript `backend self` призначений для інтерфейсів із повним стеком і пар із `runtime none`.
- tRPC орієнтований на React.
- Підтримка середовища виконання Workers залежить від комбінації інтерфейсу/бекенду.
- Бібліотеки інтерфейсу користувача, цілі розгортання, постачальники та аддони чутливі до стеку.
- Для візуальної перевірки використовуйте [Матрицю сумісності](/docs/reference/compatibility/) або [Stack Builder](__BFS0__).
