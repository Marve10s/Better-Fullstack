```npm
npm create better-fullstack@latest telemetry status
npm create better-fullstack@latest telemetry disable
npm create better-fullstack@latest telemetry enable
```

`status --json` prints the effective state, saved preference, and environment override. `BTS_TELEMETRY_DISABLED=1` takes precedence over the saved preference.

## Collected when enabled

Official CLI releases enable anonymous telemetry by default after a one-time notice; preview builds disable it.

- Bounded stack/capability identifiers and counts.
- Command state, success/failure, duration, and bounded quality counts such as conflicts, warnings, changed files, or manual-review items.
- CLI/runtime version, OS family, CI boolean/provider, and invocation source.
- A random anonymous install ID used only for unique, active, and repeat-use aggregates.
- Bounded selection outcome IDs for create completion, starter-track use, compatibility recovery,
  abandoned plans, chosen evidence level, and problem class.

## Never collected

Project names, filesystem paths, filenames, source code, recommendation briefs or prompts, env keys or values, secrets, URLs, runtime logs, raw error messages, and personal information are excluded at both the CLI and ingest boundaries.

Delivery is best-effort with a one-second timeout and can never fail a command. Programmatic `create()` disables analytics by default, and CLI creation accepts `--disable-analytics`.

## Browser analytics

The Stack Builder uses a separate browser-local anonymous ID for bounded run, edit, and ZIP outcomes. One browser preference gates Vercel Web Analytics, Speed Insights, and the product-event stream together. Do Not Track and Global Privacy Control disable all three. Campaign attribution accepts only published campaign identifiers; arbitrary URL values are discarded.

## Decision coverage

The private decision room treats an event as eligible only when it represents a terminal selection
decision, such as create completion, a builder handoff, compatibility recovery, or an abandoned
plan. A decision is covered when it also contains a bounded stage, outcome, and evidence level.
Failed creates and abandoned plans additionally require a bounded problem class.

Coverage is `covered decisions / eligible decisions`. General page views and command starts are
not part of the denominator. Window reporting activates at 80 percent coverage; otherwise the
decision room falls back to current all-time aggregates. Old aggregates use a different version
and are excluded instead of being reinterpreted as covered.

Problem classes separate `discoverability`, `missing-capability`, `compatibility`, and
`reliability`. These are fixed identifiers, not user text. Repeat lifecycle use counts terminal
existing-project actions on distinct UTC dates. It does not treat general visits or creation alone
as lifecycle return.

Production reporting still requires the maintenance-owner activation and reconciliation drill.
Repository tests prove the contract and aggregation behavior, but they do not prove that a deployed
environment has reached 80 percent coverage.
