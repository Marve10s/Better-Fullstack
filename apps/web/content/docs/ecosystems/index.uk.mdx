Better Fullstack використовує один CLI для кількох екосистем. Кожна екосистема має власну поверхню каркаса, ланцюжок інструментів і правила сумісності.

Для пакетів продуктів, які охоплюють мови, використовуйте [режим мультиекосистеми](/docs/ecosystems/multi-ecosystem/). Він моделює проект як частини стеку, такі як `frontend:typescript:next`, `backend:go:gin`, `backend.orm:go:gorm` та `database:universal:postgres`.

| Екосистема | Найкраще для | Примітки |
| --- | --- | --- |
| [TypeScript](/docs/ecosystems/typescript/) | Fullstack web, APIs, робочі, настільні та найбільша матриця веб-інтеграції. | Веб-параметри TypeScript-first. |
| [React Native](/docs/ecosystems/react-native/) | Мобільні програми Expo з навігацією, інтерфейсом користувача, сховищем, тестуванням, push, OTA та глибоким посиланням. | Використовує поверхню екосистеми React Native замість категорій веб-інтерфейсу TypeScript. |
| [Rust](/docs/ecosystems/rust/) | Бекенд-сервіси, програми CLI, GraphQL/gRPC, веб-інтерфейси Rust та строго типізовані бібліотеки. | Використовує Cargo; шаблони залежать від вибраних параметрів Rust. |
| [Python](/docs/ecosystems/python/) | Сервіси, орієнтовані на API та AI, з інфраструктурою, ORM, перевіркою, чергою, GraphQL і вибором якості. | Використовує `uv`; Python AI — це окрема категорія множинного вибору. |
| [Go](/docs/ecosystems/go/) | API служби, gRPC, CLIs, журналювання, ORM і Go помічники автентифікації. | Використовує модулі Go; GoBetterAuth вибрано за допомогою глобального `--auth go-better-auth`. |
| [Java](/docs/ecosystems/java/) | Проекти Spring Boot, Quarkus або звичайні Java з Maven/Gradle, постійністю, авторизацією, бібліотеками та тестами. | Java використовує обгортки Maven або Gradle, коли вибрано інструмент збірки. |
| [Elixir](/docs/ecosystems/elixir/) | Програми Phoenix та Phoenix LiveView з функціями Ecto, Absinthe, реального часу, завдань, тестування, якості та розгортання. | Використання суміші; кілька параметрів на рівні схеми залишаються вимкненими, доки шаблони не наздоженуть. |
| [.NET](/docs/ecosystems/dotnet/) | Основні служби ASP.NET з EF Core або Dapper, Identity, Minimal APIs або Hot Chocolate, SignalR, завданнями та тестами. | Використовує .NET SDK; тестування та спостережливість є категоріями, які можна вибрати. |

## Базовий рівень за замовчуванням CLI

Прийняття стандартних значень створює веб-проект TypeScript. Менеджер пакетів слідує за менеджером пакунків, який використовується для запуску CLI.

```json
{
  "ecosystem": "typescript",
  "frontend": ["tanstack-router"],
  "backend": "hono",
  "runtime": "bun",
  "database": "sqlite",
  "orm": "drizzle",
  "auth": "better-auth",
  "api": "trpc",
  "cssFramework": "tailwind",
  "uiLibrary": "shadcn-ui",
  "testing": "vitest",
  "addons": ["turborepo"],
  "versionChannel": "stable",
  "aiDocs": ["claude-md"]
}
```

Середа виконання та менеджер пакунків — це окремі варіанти. Наприклад, створений проект TypeScript може використовувати npm, pnpm, Yarn або Bun для встановлення, вибираючи Bun як середовище виконання програми.

## Спільні параметри не є універсальними

Деякі прапори є глобальними, оскільки вони зберігаються в одній конфігурації проекту, але не кожен прапор застосовується до кожної екосистеми. Використовуйте сторінки екосистеми нижче для того, що згенеровано, і використовуйте [Довідкові параметри](/docs/reference/options/) для точних значень CLI.
