Recipes start with a concrete product shape and finish with a running or verified project. They use
explicit commands when reproducibility matters and call out the toolchains each generated stack
needs.

| Recipe                                                              | Best for                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| [Default TypeScript web app](/docs/recipes/default-typescript-web/) | The fastest supported fullstack starting point.                          |
| [Next.js self-backend app](/docs/recipes/nextjs-self-backend/)      | One Next.js application with PostgreSQL, Drizzle, and auth.              |
| [Python API](/docs/recipes/python-api/)                             | A FastAPI service managed with `uv`.                                     |
| [.NET service](/docs/recipes/dotnet-service/)                       | An ASP.NET Core API with EF Core and PostgreSQL.                         |
| [Multi-ecosystem product](/docs/recipes/multi-ecosystem-product/)   | A web frontend and backend service in different languages.               |
| [Browser ZIP workflow](/docs/recipes/browser-zip-workflow/)         | Previewing, running, editing, and downloading without a local CLI first. |

For command selection after the first scaffold, see the [Project Lifecycle](/docs/getting-started/lifecycle/).
