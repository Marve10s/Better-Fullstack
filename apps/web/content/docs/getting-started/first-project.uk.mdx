У цьому покроковому керівництві створюється проект, переглядається те, що може створити CLI, і показується, де слід дивитися після завершення каркасу.

## 1. Створіть проект

Запустіть майстер:

```npm
npm create better-fullstack@latest my-app
```

Прийміть значення за замовчуванням для TypeScript стартера або змініть підказки відповідно до потрібного стеку.

## 2. Попередній перегляд без запису

Використовуйте `--dry-run`, якщо ви хочете спочатку перевірити згенероване дерево файлів:

```npm
npm create better-fullstack@latest my-app -- --dry-run
```

Пробний запуск корисний перед спробою нової екосистеми, цілі розгортання або багатоекосистемного стеку.

## 3. Ліска з команди

Явні прапори роблять каркас повторюваним. У цьому прикладі створюється проект Next.js із самостійним сервером і пропускається встановлення/Git, щоб ви могли спочатку переглянути файли:

```npm
npm create better-fullstack@latest my-app -- \
  --ecosystem typescript \
  --frontend next \
  --backend self \
  --runtime none \
  --database postgres \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --db-setup none \
  --ai none \
  --payments none \
  --examples none \
  --addons none \
  --ai-docs none \
  --version-channel stable \
  --no-install \
  --no-git
```

<Callout kind="info" title="Prompt behavior">
Явні прапори пропускають категорії, які вони охоплюють. `--yes` приймає значення за замовчуванням і конфліктує з прапорами основного стеку, такими як `--frontend`, `--backend` і `--database`. Використовуйте `none` для додаткових категорій, які потрібно вимкнути.
</Callout>

## 4. Встановіть залежності

Якщо ви використовували `--no-install`, встановіть вручну всередині проекту:

```bash
cd my-app
```

```npm
npm install
```

Екосистеми рідної мови використовують власні інструменти:

```bash
cargo build
uv sync
go mod tidy
./mvnw test
./gradlew test
```

## 5. Перегляньте проект

Згенеровані проекти включають:

- `bts.jsonc` з вибраним стеком і посиланням на схему.
- Фреймворк, пакет і файли конфігурації для вибраної екосистеми.
- Відтворювана команда, надрукована CLI.
- Додаткові документи AI, наприклад `CLAUDE.md`, `Agents.md` або `.cursorrules`.
- README та примітки до налаштування, якщо їх надають вибрані шаблони.

## 6. Додайте підтримувані функції пізніше

У створеному проекті використовуйте `add` для підтримуваних аддонів:

```npm
npm create better-fullstack@latest add -- --addons mcp skills
```

Команда `add` зчитує `bts.jsonc`, пропускає наявні надбудови та друкує вказівки щодо встановлення, якщо залежності не встановлено автоматично.
