This walkthrough creates a project, previews what the CLI can generate, and shows where to look after the scaffold finishes.

## 1. Create a project

Run the wizard:

```npm
npm create better-fullstack@latest my-app
```

Accept the defaults for a TypeScript starter, or change the prompts to match the stack you want.

## 2. Preview without writing

Use `--dry-run` when you want to inspect the generated file tree first:

```npm
npm create better-fullstack@latest my-app -- --dry-run
```

The dry run is useful before trying a new ecosystem, deployment target, or multi-ecosystem stack.

## 3. Scaffold from a command

Explicit flags make the scaffold repeatable. This example creates a Next.js self-backend project and skips install/Git so you can review files first:

```npm
npm create better-fullstack@latest my-app -- \
  --ecosystem typescript \
  --frontend next \
  --backend self \
  --runtime none \
  --database postgres \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --db-setup none \
  --css-framework tailwind \
  --ui-library shadcn-ui \
  --shadcn-base radix \
  --shadcn-style nova \
  --shadcn-icon-library lucide \
  --shadcn-color-theme neutral \
  --shadcn-base-color neutral \
  --shadcn-font geist \
  --shadcn-radius default \
  --ai none \
  --payments none \
  --examples none \
  --ai-docs none \
  --version-channel stable \
  --no-install \
  --no-git
```

<Callout kind="info" title="Prompt behavior">
Explicit flags skip the categories they cover. `--yes` accepts defaults and conflicts with core stack flags such as `--frontend`, `--backend`, and `--database`. Use `none` for optional categories you want disabled.
</Callout>

## 4. Install dependencies

If you used `--no-install`, install manually inside the project:

```bash
cd my-app
```

```npm
npm install
```

Language-native ecosystems use their own tools:

```bash
cargo build
uv sync --extra dev
go mod tidy
./mvnw test
./gradlew test
mix deps.get
dotnet restore
```

## 5. Run and verify the project

For the default TypeScript scaffold, start the generated development scripts:

```npm
npm run dev
```

Open the web URL printed by the command and confirm that the starter page loads. If the stack has a
separate backend, confirm its health or example endpoint using the URL printed in the terminal. Stop
the processes before continuing.

Language-native entrypoints vary with the selected framework, so the generated README is the command
authority:

| Ecosystem    | Typical development command                                                          |
| ------------ | ------------------------------------------------------------------------------------ |
| React Native | Package-manager `start` script, followed by the Expo simulator/device workflow       |
| Rust         | `cargo run` or the workspace command named in the README                             |
| Python       | The `uv run ...` command named for the selected framework                            |
| Go           | `go run ...` for the generated `main` package                                        |
| Java/Kotlin  | `./mvnw spring-boot:run`, `./gradlew bootRun`, or the generated framework equivalent |
| Elixir       | `mix phx.server` for Phoenix projects                                                |
| .NET         | `dotnet run` with the generated project path when required                           |

Run the generated test/check command after the first successful startup. Do not assume one universal
command across ecosystems.

## 6. Inspect the project

Generated projects include:

- `bts.jsonc` with the selected stack and schema reference.
- Framework, package, and config files for the selected ecosystem.
- A reproducible command printed by the CLI.
- Optional AI docs such as `CLAUDE.md`, `AGENTS.md`, or `.cursorrules`.
- README and setup notes where the selected templates provide them.

## 7. Change the selected stack later

Inside a generated project, use `add` for capabilities and stack selections. Preview the plan
first:

```npm
npm create better-fullstack@latest add -- --email resend --dry-run
npm create better-fullstack@latest add -- --email resend
```

The `add` command reads `bts.jsonc`, skips selections already present, protects generated files that
you changed, and prints install guidance when dependencies are not installed automatically.

## 8. Check and update the scaffold

```npm
npm create better-fullstack@latest check -- --skip-checks
npm create better-fullstack@latest update
```

`check` diagnoses config, dependencies, env files, and optionally native/build checks. `update`
defaults to a review-only template-drift plan. Review the categorized paths and pass that exact plan
token. Apply creates a recovery point and rolls failed writes back. The additional
`--acknowledge-unproven-manifest-v1` flag is required only for migrated or manually adopted
manifests whose original lineage remains unverified.
