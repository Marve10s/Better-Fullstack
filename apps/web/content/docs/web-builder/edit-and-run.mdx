Edit & Run creates a disposable generated project and executes it inside a browser WebContainer. It
does not deploy the project or send edited source files to Better Fullstack.

## Supported stacks

The Run view currently requires all of the following:

- Solo mode.
- The TypeScript ecosystem.
- At least one web frontend.
- A frontend other than Redwood, whose generated layout does not expose the root development script
  the runner needs.
- A browser that supports the WebContainer runtime.

Native and multi-ecosystem projects can still use Preview and ZIP download, but they must run with
their native toolchains after download.

## Runtime flow

1. The browser generates the project from the selected stack.
2. The execution copy uses npm because WebContainers provide Node and npm. This does not change the
   package manager selected for downloads or CLI scaffolds.
3. Files are mounted in the WebContainer and dependencies are installed.
4. The generated `dev:web` or `dev` script starts and its preview URL appears in the panel.

Dependency installation requires network access from the browser runtime and can take longer on the
first run. Runtime logs stay in the browser panel.

## Editing and rerunning

Select a text file from the generated file tree and edit it in the code pane. Binary template assets
are view-only. Changes live in the disposable browser workspace; choose **Save & rerun** to sync them
to the running project. Editing `package.json` triggers another dependency install.

Discard restores the last contents successfully synced to the runtime. Stop terminates the current
development server. Reloading or leaving the page destroys the WebContainer and unsaved edits.

<Callout kind="warning" title="Download uses the selected stack">
The normal ZIP action regenerates from the selected stack. It does not export edits made inside the
disposable Edit & Run workspace. Copy important experiments before leaving the page.
</Callout>

## Privacy

Better Fullstack records bounded anonymous run outcomes such as started, ready, failed stage,
duration, retry, ecosystem, and capability IDs. It never records edited source, filenames, runtime
logs, URLs, env values, or raw errors. One browser-local preference gates both Vercel and Convex
analytics, and Do Not Track disables both. Review or change the preference in [Anonymous
Telemetry](/docs/cli/telemetry/).
