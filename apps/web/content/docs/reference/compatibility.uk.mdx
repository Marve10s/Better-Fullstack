Better Fullstack перевіряє вибір стеку перед створенням. Конструктор, сервер CLI і MCP використовують однакову логіку сумісності, тому недійсні комбінації відхиляються або коригуються послідовно.

<CompatibilityMatrix />

## Що перевіряє

- Чи сумісний параметр із вибраним базовим стеком.
- Спільна вимкнена причина блокування комбінації.
- Будь-які нотатки про автоматичне налаштування з того самого аналізатора сумісності, який використовується розробником.

## Як ним користуватися

1. Виберіть екосистему.
2. Налаштуйте базові поля стека, які мають значення для вашого запитання.
3. Виберіть категорію для перевірки.
4. Перегляньте, які параметри сумісні та чому заблоковано.

Це практична матриця, а не кожна можлива попарна комбінація. Для повної перевірки проекту запустіть CLI, скористайтеся Stack Builder або викличте `bfs_check_compatibility` через MCP перед створенням каркасу.

## Поведінка сумісності

- `none` вимикає додаткові категорії, якщо вони підтримуються.
- Деякі параметри активують автоматичне коригування, як-от Convex замінює базу даних, що належить серверній системі/API.
- Деякі варіанти інтерфейсу навмисно звужують API, інтерфейс користувача, середовище виконання або підтримку розгортання.
- Java, Rust, Python та Go використовують категорії, пов’язані з екосистемою, замість повної поверхні стеку TypeScript.
