
## Що це створює

- Проект Rust API з використанням Axum.
- PostgreSQL як параметр бази даних.
- SeaORM для доступу до бази даних.
- Трасування для структурованого журналювання.
- У будь-якому випадку та у стилі обробки помилок Thiserror.

## Згенерована форма

Цей стек призначений для створення серверної служби, а не програми повного стеку. Згенерований проект дає вам введену межу HTTP в Axum, рівень бази даних, що належить SeaORM, і журналювання в області запиту через `tracing`.

Важливими межами реалізації є:

- Маршрути залишаються тонкими та перетворюють вхідні дані HTTP у виклики програми.
- Моделі та сутності SeaORM відображають власну базу даних.
- Помилки моделюються явно, а потім перетворюються у відповіді HTTP на межі.
- Конфігурація зчитується один раз під час запуску, тому пули баз даних, маршрутизатори та ведення журналів можуть передбачувано підключатися.

## Репрезентативне дерево файлів

Точні назви файлів можуть змінюватися в міру розвитку генератора, але це форма, яку можна очікувати від Axum API з PostgreSQL і SeaORM:

```txt
my-rust-api/
  Cargo.toml
  .env.example
  src/
    main.rs
    config.rs
    error.rs
    routes/
      mod.rs
      health.rs
      users.rs
    entities/
      mod.rs
      prelude.rs
      user.rs
    services/
      mod.rs
      users.rs
```

Використовуйте `routes/` для механізмів HTTP, `services/` для поведінки додатків і `entities/` для створених або підтримуваних типів моделей бази даних SeaORM.

## Приклади маршруту та моделі

Обробник Axum зазвичай повинен приймати витягнутий стан і введені дані запиту, а потім повертати результат, який ваш спільний тип помилки може перетворити на відповідь:

```rust
use axum::{extract::State, Json};
use serde::{Deserialize, Serialize};

use crate::{error::AppError, services::users::UserService, AppState};

#[derive(Debug, Deserialize)]
pub struct CreateUserRequest {
    pub email: String,
    pub name: String,
}

#[derive(Debug, Serialize)]
pub struct UserResponse {
    pub id: i32,
    pub email: String,
    pub name: String,
}

pub async fn create_user(
    State(state): State<AppState>,
    Json(input): Json<CreateUserRequest>,
) -> Result<Json<UserResponse>, AppError> {
    let user = UserService::new(state.db)
        .create(input.email, input.name)
        .await?;

    Ok(Json(UserResponse {
        id: user.id,
        email: user.email,
        name: user.name,
    }))
}
```

SeaORM зберігає вставки явними через активні моделі:

```rust
use sea_orm::{ActiveModelTrait, ActiveValue::Set, DatabaseConnection};

use crate::entities::user;

pub async fn create_user(
    db: &DatabaseConnection,
    email: String,
    name: String,
) -> Result<user::Model, sea_orm::DbErr> {
    user::ActiveModel {
        email: Set(email),
        name: Set(name),
        ..Default::default()
    }
    .insert(db)
    .await
}
```

## Примітки щодо сумісності

<GuideCompatibilityNote kind="supported" title="Compatibility rule">
  Зберігайте `--rust-web-framework axum`, `--database postgres` і `--rust-orm sea-orm` разом, якщо вам потрібна форма цього посібника. Якщо ви зміните ORM на `sqlx`, очікуйте більше рукописного SQL і менше типів моделей у стилі сутності. Якщо ви встановите `--rust-web-framework none`, приклади маршрутів у цьому посібнику більше не застосовуються.
</GuideCompatibilityNote>

## Коли його вибрати

Виберіть Axum, якщо продуктивність, правильність і чіткий код сервера мають значення. Він добре підходить для API, серверних служб і систем, де система типів Rust є частиною стратегії продукту.

## Компроміси

Rust зазвичай вимагає більш початкового моделювання типу, ніж TypeScript, Python або Go. Натомість ви отримуєте надійні перевірки під час компіляції та передбачувану поведінку під час виконання.

SeaORM є продуктивним, якщо вашій команді потрібні згенеровані типи сутностей і компонувальники запитів. Це може здатися важчим, ніж SQLx, для служб із інтенсивними запитами, де рукописний SQL є частиною дизайну.

## Примітки щодо тестування та розгортання

Почніть з тестування обробників і служб окремо. Тести обробників можуть створити маршрутизатор Axum із тестовим станом, тоді як тести служб можна запускати з одноразовою базою даних PostgreSQL.

```bash
cargo test
```

Перед розгортанням переконайтеся, що середовище виконання надає рядок підключення PostgreSQL та будь-який крок міграції, який використовує ваш проект. Для виробництва зберігайте `RUST_LOG` явним, щоб виведення трасування було корисним, але не надто шумним:

```bash
RUST_LOG=info cargo run
```

## Усунення несправностей

- Якщо програма запускається, але виклики бази даних не вдаються, переконайтеся, що згенеровані ключі `.env.example` відповідають змінним, установленим у вашій оболонці або платформі розгортання.
- Якщо типи SeaORM не відповідають базі даних, повторно запустіть сутність проекту або робочий процес міграції замість того, щоб вручну редагувати створений код.
- Якщо помилки повертаються як загальні відповіді 500, перевірте спільний тип помилки та його реалізацію `IntoResponse`.
- Якщо в журналах відсутній контекст запиту, переконайтеся, що передплатник трасування ініціалізований, перш ніж маршрутизатор почне обслуговувати трафік.
