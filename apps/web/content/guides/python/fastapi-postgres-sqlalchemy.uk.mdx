## Що це створює

- Проект Python з використанням FastAPI.
- PostgreSQL як параметр бази даних.
- SQLAlchemy для доступу до бази даних.
- Пидантичний для перевірки.
- Ruff для якості коду Python.
- Файл конфігурації Better Fullstack для повторюваних риштувань.

## Згенерована форма

Скаффолд — це компактна служба API, а не повне монорепо. FastAPI володіє кордоном HTTP, SQLAlchemy володіє постійністю, а Pydantic володіє контрактами запитів і відповідей. Створена програма містить перевірки працездатності, зразок коду користувача та пост-код CRUD, підключення сеансу бази даних, конфігурацію Alembic і тести.

```txt
my-fastapi-api/
├── pyproject.toml
├── alembic.ini
├── migrations/
│   ├── env.py
│   └── versions/
├── src/app/
│   ├── main.py
│   ├── database.py
│   ├── models.py
│   ├── schemas.py
│   └── crud.py
└── tests/
    ├── test_main.py
    └── test_database.py
```

URL-адреса бази даних за замовчуванням повертається до локальної SQLite, тому проект може завантажитися негайно. Оскільки в цьому посібнику вибрано `--database postgres`, згенеровані залежності включають `psycopg[binary]`; встановіть `DATABASE_URL` на рядок з’єднання PostgreSQL, якщо ви хочете використовувати справжню цільову базу даних.

```bash
DATABASE_URL="postgresql+psycopg://postgres:postgres@localhost:5432/my_fastapi_api"
```

## Коли його вибрати

Виберіть FastAPI для APIs, AI-суміжних служб, внутрішніх платформ і серверних служб, де доступ до екосистеми Python має значення.

FastAPI краще підходить, ніж Django, якщо вам потрібні чіткі функції маршруту, OpenAPI-моделювання першого запиту/відповіді та невелика площа проекту. Django краще підходить, якщо вам потрібні його адміністративні конвенції, структура додатків і зрілі вбудовані стандартні веб-фреймворки.

| Точка прийняття рішення | FastAPI + SQLAlchemy | Django REST API |
| --- | --- | --- |
| Форма проекту | Невеликий сервіс із зрозумілими модулями | Конвенційний проект Django |
| API моделювання | Пидантичні схеми, близькі до маршрутів | Серіалізатори DRF/перегляди на угодах Django |
| Адмін/бек-офіс | Додайте окремо | Екосистема адміністратора Django — це природний шлях |
| Асинхронно-суміжна робота | Загальна придатність для меж служби API та AI | Можливо, але менш мінімально |
| Налаштування ORM | SQLAlchemy-first | Django ORM є звичайним, хоча цей стек записує вибір SQLAlchemy |

## Представницькі фрагменти

Згенерований шар моделі використовує зіставлені стовпці стилю SQLAlchemy 2. Розширте зразки моделей `User` і `Post` замість того, щоб додавати логіку бази даних безпосередньо в обробники маршрутів.

```python
from datetime import datetime

from sqlalchemy import DateTime, Integer, String, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, index=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True, nullable=False)
    name: Mapped[str | None] = mapped_column(String(255), nullable=True)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
    )
```

Маршрути залежать від сеансу бази даних для кожного запиту та делегують постійність `crud.py`.

```python
from fastapi import Depends, HTTPException
from sqlalchemy.orm import Session

from app import crud
from app.database import get_db
from app.schemas import UserCreate, UserResponse


@app.post("/users", response_model=UserResponse)
def create_user(user: UserCreate, db: Session = Depends(get_db)):
    existing = crud.get_user_by_email(db, user.email)
    if existing is not None:
        raise HTTPException(status_code=400, detail="Email already registered")

    return crud.create_user(db, user)
```

## Міграції та тести

Згенерована програма може створювати таблиці під час запуску для швидкого локального циклу, але виробничі групи повинні використовувати міграції Alembic як джерело історії змін бази даних.

```bash
uv run ruff check .
uv run pytest
```

Коли ви додаєте або змінюєте моделі, створіть міграцію та перегляньте її перед застосуванням:

```bash
uv run alembic revision --autogenerate -m "add account status"
uv run alembic upgrade head
```

Тримайте тести розділеними на поведінку маршруту та поведінку бази даних. Тести маршруту повинні використовувати тестовий клієнт FastAPI і затверджувати коди статусу HTTP, тоді як тести бази даних повинні створювати ізольований механізм тестування або межу транзакції.

## Примітки до розгортання

Запустіть програму за сервером ASGI, таким як Uvicorn. У виробництві встановіть `DATABASE_URL`, вимкніть широкі джерела CORS і запустіть міграції перед запуском нових екземплярів програми.

```bash
uv run alembic upgrade head
uv run uvicorn app.main:app --host 0.0.0.0 --port "${PORT:-8000}"
```

Якщо ваша платформа розгортання створюється з кореня сховища, переконайтеся, що вона встановлює залежності проекту Python від `pyproject.toml` і вказує `PYTHONPATH` або робочий каталог у згенерованому макеті пакета.

## Усунення несправностей

| Симптом | Перевірте |
| --- | --- |
| `psycopg` помилки підключення | Підтвердьте, що `DATABASE_URL` використовує URL-адресу PostgreSQL, доступну з середовища виконання програми. |
| Таблиці існують локально, але не у виробництві | Перед завантаженням запустіть міграцію Alembic для робочої бази даних. |
| Помилки імпорту для `app.main` | Почніть із кореня проекту або послідовно налаштуйте вихідний каталог. |
| CORS працює локально, але не вдається розгорнути в браузері | Замініть символ підстановки CORS на розгорнуте джерело інтерфейсу. |

## Компроміси

FastAPI є сильним API за замовчуванням. Якщо вам потрібен більш автономний веб-фреймворк і конвенції в стилі адміністратора, порівняйте його з Django.
