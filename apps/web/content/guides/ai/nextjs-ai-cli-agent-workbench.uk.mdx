Використовуйте цей стек, якщо вам потрібен проект Next.js, підготовлений для робочих процесів розробки за допомогою AI, локального інструментарію MCP та створеної документації агента.

```npm
npm create better-fullstack@latest my-agent-workbench -- \
  --ecosystem typescript \
  --frontend next \
  --backend self \
  --database sqlite \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --ai ai-cli \
  --addons mcp skills \
  --ai-docs claude-md agents-md cursorrules \
  --css-framework tailwind \
  --ui-library shadcn-ui \
```

## Що це створює

- Програма Next.js з локальним налаштуванням повного стеку.
- SQLite і Drizzle.
- Better Auth.
- Конфігурація AI CLI.
- MCP і додатки Skills.
- Файли документації для агента, такі як `CLAUDE.md`, `AGENTS.md` або `.cursorrules` залежно від вибраних позначок.

## Згенерована форма

Цей стиль є як скелетом програми, так і скелетом робочого процесу агента. Веб-програма є звичайним проектом повного стеку Next.js, тоді як надбудови створюють контекст сховища для агентів кодування та локальних інструментів AI.

Представницька форма:

```txt
my-agent-workbench/
  bts.jsonc
  AGENTS.md
  CLAUDE.md
  .cursorrules
  app/
  components/
  lib/
    auth/
    db/
```

Точні файли документації залежать від `--ai-docs claude-md agents-md cursorrules`. Показана команда запитує всі три, щоб різні інструменти агента могли знайти керівництво проектом у бажаному форматі.

## Як підходять елементи AI

`--ai ai-cli` вибирає підтримку AI CLI. `--addons mcp skills` додає можливості локального агента навколо MCP та навички. `--ai-docs` контролює, які файли інструкцій сховища генеруються.

Використовуйте ці частини для різних робіт:

| Шматок | призначення | Типове використання |
| --- | --- | --- |
| AI CLI | Робочий процес локального командного рядка AI | Виконання завдань проекту за допомогою агента |
| MCP | Інструмент/контекстний міст | Expoрозповсюджувати можливості проекту або служби для агентів |
| Навички | Інструкції для багаторазового використання засобу | Стандартизація робочих процесів, таких як налагодження чи робота над функціями |
| Документи агента | Керівництво репозиторію | Повідомлення агентам, як структурований цей проект |

## Приклад інструкції агента

Документи для агентів мають бути конкретними. Віддайте перевагу правилам проекту, яких можна дотримуватися та перевірити:

```md
## Verification

After editing authentication, run the smallest auth-related test or typecheck.
Do not run broad workspace commands unless the change crosses package boundaries.

## Project boundaries

Database access belongs in server-only modules.
Client components should call typed API helpers instead of importing Drizzle code.
```

Зберігайте ці документи в актуальному стані під час зміни архітектури. Застарілі інструкції агента гірші, ніж відсутність інструкцій, оскільки вони впевнено направляють майбутню роботу до неправильних файлів.

## Приклад прикладної моделі

Сторона програми залишається звичайним стеком Better Fullstack TypeScript. Маленька таблиця SQLite може виглядати так:

```ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const agentRun = sqliteTable("agent_run", {
  id: text("id").primaryKey(),
  goal: text("goal").notNull(),
  status: text("status").notNull(),
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
});
```

Використовуйте прикладні таблиці для даних продукту, а не для зберігання секретів. Облікові дані MCP, маркери постачальника та службові ключі AI мають зберігатися в змінних середовища або безпечному сховищі постачальника.

## Коли його вибрати

Виберіть це, коли саме сховище повинно бути легким для розуміння та модифікації агентами кодування. Це корисно для команд, які стандартизують робочі процеси агентів, інструменти MCP та створений контекст проекту.

## Примітки щодо сумісності

- Цей стиль використовує програму TypeScript Next.js з `--backend self`, тому Next.js володіє межею сервера.
- `--addons mcp skills` — це доповнення до робочого процесу розробки. Вони не замінюють параметри автентифікації програми, бази даних або API.
- `--ai-docs claude-md agents-md cursorrules` навмисно генерує кілька форматів інструкцій для різних інструментів.
- SQLite зручний для локальних проектів у стилі верстака. Використовуйте PostgreSQL, якщо робоче місце стає багатокористувацьким виробничим продуктом зі спільним станом.

## Примітки до розгортання

Розгорніть програму Next.js як звичайну програму повного стеку: налаштуйте секрети Better Auth, URL-адресу програми та параметри бази даних. Розглядайте ключі постачальника AI, облікові дані MCP та будь-які маркери інструментів як секрети на стороні сервера.

Документи агента зазвичай належать до системи керування джерелами. Локальні облікові дані, згенеровані журнали та конфігурація MCP для конкретного комп’ютера зазвичай цього не роблять. Перегляньте згенеровані файли ігнорування перед тим, як закріпити.

## Усунення несправностей

- Якщо інструмент AI ігнорує вказівки щодо сховища, підтвердьте, що він читає згенероване ім’я файлу, яке ви вибрали за допомогою `--ai-docs`.
- Якщо інструменти MCP недоступні, перевірте локальні налаштування MCP та чи вказано на нього агент-споживач.
- Якщо під час виконання сценаріїв з’являється підказка про налаштування надбудови, використовуйте явні позначки, як це робить цей посібник, щоб стандартні параметри були детермінованими.
- Якщо програма працює локально, але автентифікація не вдається після розгортання, перевірте ту саму URL-адресу Better Auth та налаштування файлів cookie, які ви б перевірили в будь-якому стеку Next.js.

## Компроміси

Цей стек більш самовпевнений, ніж мінімальний початковий Next.js. Якщо вам потрібна лише програма продукту без засобів агента, використовуйте [Next.js з Drizzle і Better Auth](/guides/typescript/nextjs-drizzle-better-auth/).

Додаткові файли є цінними, коли люди та агенти постійно працюють у сховищі. Вони накладні для одноразового прототипу. Якщо команда не підтримує інструкції, почніть із простішого посібника Next.js та додайте документи AI пізніше.
