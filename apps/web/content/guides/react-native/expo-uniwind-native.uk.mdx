Використовуйте цей стек, якщо вам потрібна програма Expo для мобільних пристроїв і вам не потрібен згенерований бекенд у тому самому каркасі.

```npm
npm create better-fullstack@latest my-mobile-app -- \
  --ecosystem react-native \
  --frontend native-uniwind \
  --mobile-navigation expo-router \
  --mobile-ui uniwind \
  --mobile-storage mmkv \
  --mobile-testing maestro-react-native-testing-library \
  --mobile-push expo-notifications \
  --mobile-ota expo-updates \
  --mobile-deep-linking expo-linking \
  --ai-docs none \
  --no-install
```

## Що це створює

- Рідна програма Expo, яка використовує Uniwind.
- Expo Маршрутизатор для власних маршрутів на основі файлів.
- Сховище MMKV, бібліотека тестування React Native, Maestro, push-повідомлення, оновлення OTA та глибокі посилання.
- За замовчуванням немає веб-інтерфейсу, серверної частини, бази даних, ORM, авторизації або рівня API.
- Форма проекту для мобільних пристроїв, яку пізніше можна поєднати з API.

## Згенерована форма

Ця команда створює власну основу зовнішнього інтерфейсу, а не веб-програму повного стеку. Він утримує рішення серверної частини поза початковим каркасом, щоб мобільний додаток пізніше міг вказувати на існуючу API або окремо згенеровану службу.

Представницька форма:

```txt
my-mobile-app/
  bts.jsonc
  app/
  components/
  package.json
  maestro/
```

Точні шляхи Expo можуть залежати від версії шаблону, але право власності є простим: рідні екрани та компоненти живуть у програмі, тоді як проблеми з сервером навмисно відсутні.

## Приклад екрану

Uniwind дозволяє використовувати класи утилітного стилю в компонентах React Native:

```tsx
import { Text, View } from "react-native";

export default function HomeScreen() {
  return (
    <View className="flex-1 items-center justify-center bg-white px-6">
      <Text className="text-2xl font-semibold text-slate-950">
        Mobile app
      </Text>
      <Text className="mt-2 text-center text-slate-600">
        Connect an API when the product contract is ready.
      </Text>
    </View>
  );
}
```

Тримайте API клієнтів за невеликим модулем, коли ви додаєте серверну частину. Це полегшує заміну місцевих, проміжних і робочих джерел API без зміни екранів.

## Примітки щодо сумісності

React Native — це власна екосистема в Better Fullstack. Використовуйте `--ecosystem react-native`; не поєднуйте прапорці веб-інтерфейсу TypeScript з рідними прапорцями інтерфейсу.

У цьому посібнику навмисно не включено серверну частину, базу даних, ORM, автентифікацію та генерацію API. Мобільна автентифікація та сервер API потребують рішень, пов’язаних із платформою, які краще приймати після визначення вимог до продукту.

## Коли його вибрати

Виберіть це для мобільних прототипів, додатків-супутників і власних основ програм, де API можна створювати окремо.

## Додавання API пізніше

Типовими наступними кроками є Hono API для полегшеного бекенду TypeScript, веб-програма Next.js або TanStack Start, якщо вам також потрібна веб-платформа, або спеціальний бекенд, який уже існує за межами Better Fullstack.

Додаючи API, вирішіть, як рідна програма оброблятиме:

- Базові URL-адреси API для середовища.
- Зберігання сеансу авторизації на пристрої.
- Оновити токени або поновити сеанс.
- Поведінка в автономному режимі та оптимістичні оновлення.
- Власні профілі збірки для розробки, попереднього перегляду та виробництва.

## Примітки до розгортання

Розгортання Expo відрізняється від розгортання в Інтернеті. Плануйте власні профілі збірки, ідентифікатори програми, облікові дані для підпису та змінні середовища, які використовуються під час збірки. Не додавайте секрети сервера в мобільний пакет; рідні програми повинні викликати серверну частину, яка зберігає секрети на стороні сервера.

## Усунення несправностей

- Якщо згенеровані веб-файли відсутні, це очікувано: цей стек використовує рідний інтерфейс і не використовує веб-інтерфейс.
- Якщо внутрішні маршрути відсутні, команда явно вибирає `--backend none`.
- Якщо стиль не застосовується, перевірте налаштування Uniwind і конфігурацію сканування класів у створеній програмі.
- Якщо виклики API працюють у симуляторі, але не на пристрої, перевірте, чи базова URL-адреса API вказує на хост, доступний із пристрою.
