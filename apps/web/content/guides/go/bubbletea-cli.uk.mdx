Використовуйте цей стек, якщо вам потрібен термінальний інтерфейс користувача Go замість веб-API.

```npm
npm create better-fullstack@latest my-go-cli -- \
  --ecosystem go \
  --go-web-framework none \
  --go-orm none \
  --go-api none \
  --go-cli bubbletea \
  --go-logging none \
  --go-auth none
```

## Що це створює

- Проект Go CLI.
- Bubble Tea як варіант інтерфейсу користувача терміналу.
- Без веб-фреймворку, ORM, gRPC або додаткових компонентів для автентифікації.

## Згенерована форма

Цей стек створює інтерактивну термінальну програму, а не сервер. Bubble Tea організовує програму навколо моделі, повідомлень, оновлень і переглядів.

Основний цикл простий:

- Модель зберігає поточний стан програми.
- Повідомлення описують введення, галочки або результати команд.
- `Update` змінює модель і повертає наступні команди.
- `View` відображає поточну модель як текст терміналу.

## Репрезентативне дерево файлів

```txt
my-go-cli/
  go.mod
  cmd/
    app/
      main.go
  internal/
    tui/
      model.go
      update.go
      view.go
```

Зберігайте побічні ефекти в командах Bubble Tea, де це можливо. Це полегшує тестування моделі та перегляду без запуску реального терміналу.

## Приклади моделювання та оновлення

Модель Bubble Tea може починатися з достатнього стану для відтворення та реагування на введення:

```go
package tui

type Model struct {
	Items    []string
	Selected int
	Quitting bool
}

func NewModel() Model {
	return Model{
		Items: []string{"Build", "Test", "Deploy"},
	}
}
```

Функція оновлення володіє змінами стану:

```go
package tui

import tea "github.com/charmbracelet/bubbletea"

func (m Model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
	switch msg := msg.(type) {
	case tea.KeyMsg:
		switch msg.String() {
		case "q", "ctrl+c":
			m.Quitting = true
			return m, tea.Quit
		case "j", "down":
			if len(m.Items) > 0 {
				m.Selected = (m.Selected + 1) % len(m.Items)
			}
		case "k", "up":
			if len(m.Items) > 0 {
				m.Selected = (m.Selected - 1 + len(m.Items)) % len(m.Items)
			}
		}
	}

	return m, nil
}
```

Подання має відображатися зі стану без виконання роботи:

```go
package tui

import "strings"

func (m Model) View() string {
	if m.Quitting {
		return ""
	}

	var b strings.Builder
	b.WriteString("Tasks\n\n")

	for i, item := range m.Items {
		cursor := " "
		if i == m.Selected {
			cursor = ">"
		}
		b.WriteString(cursor + " " + item + "\n")
	}

	b.WriteString("\nq: quit  j/k: move\n")
	return b.String()
}
```

## Примітки щодо сумісності

У проектах CLI категорії лише для сервера мають бути встановлені на `none`, якщо вони не є навмисно гібридними інструментами.

Зберігайте `--go-cli bubbletea` з `--go-web-framework none`, `--go-orm none` і `--go-api none` для термінальної програми. Якщо CLI пізніше спілкується з API, збережіть цей клієнт в окремому пакеті та викликайте його через команди, а не з `View`.

## Коли його вибрати

Виберіть Bubble Tea для інформаційних панелей терміналів, інструментів розробника та інтерфейсів командного рядка, де інтерактивність має значення.

Він добре підходить для інструментів, які потребують вибору, прогресу, форм або поточного стану без створення інтерфейсу браузера.

## Примітки щодо тестування та розгортання

Модульне тестування переходів моделі безпосередньо:

```bash
go test ./...
```

Для розповсюдження створіть єдиний двійковий файл і задокументуйте підтримувані змінні середовища або файли конфігурації:

```bash
go build ./cmd/app
```

Якщо згенерований проект використовує інший шлях команди, дотримуйтеся шляху в його каталозі `cmd/`.

## Усунення несправностей

- Якщо натискання клавіш нічого не дає, перевірте, чи сфокусований термінал надсилає послідовність клавіш, яку отримує Bubble Tea.
- Якщо на екрані залишається застарілий вихід, перевірте параметри запуску та завершення програми на альтернативну поведінку екрана.
- Якщо тести складно писати, перенесіть побічні ефекти у функції `tea.Cmd` і збережіть `Update` детермінованим.
- Якщо вивід обгортається погано, перевірте на вузькій ширині та збережіть форматування `View` відповідно до доступного простору, коли модель відстежує розміри.
