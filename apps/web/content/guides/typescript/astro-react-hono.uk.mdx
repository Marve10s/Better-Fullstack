Використовуйте цей стек, якщо вам потрібен Astro для сторінок і островів із великим вмістом, а також сервер TypeScript API.

```npm
npm create better-fullstack@latest my-astro-app -- \
  --ecosystem typescript \
  --frontend astro \
  --astro-integration react \
  --backend hono \
  --runtime bun \
  --database sqlite \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --css-framework tailwind \
  --ui-library daisyui \
```

## Що це створює

- Інтерфейс Astro з інтеграцією React.
- Сервер Hono працює на Bun.
- SQLite і Drizzle.
- Better Auth.
- tRPC, оскільки це налаштування Astro використовує інтеграцію React.
- Tailwind CSS і DaisyUI.

## Згенерована форма

Цей стек поєднує зовнішній інтерфейс Astro з окремим сервером Hono API. React острови вмикаються через `--astro-integration react`, тому tRPC доступний у цьому посібнику.

Представницька форма:

```txt
my-astro-app/
  bts.jsonc
  apps/
    web/
    server/
  packages/
    shared/
```

Сторінки Astro мають бути зосереджені на маршрутизації, вмісті та композиції островів. Hono має володіти маршрутами API, поведінкою сервера з підтримкою авторизації та доступом до бази даних.

## Приклад Astro острів

Використовуйте Astro для оболонки сторінки та React лише там, де потрібна інтерактивність:

```astro
---
import ProjectPicker from "../components/ProjectPicker.tsx";
---

<main class="mx-auto max-w-5xl p-6">
  <h1 class="text-3xl font-semibold">Project docs</h1>
  <ProjectPicker client:load />
</main>
```

Це зберігає статичні або переважно статичні сторінки дешевими, водночас дозволяючи інтерактивним компонентам React викликати введений API.

## Приклад кінцевої точки Hono

Перевірки справності та прості кінцеві точки обслуговування належать до Hono:

```ts
import { Hono } from "hono";

const app = new Hono();

app.get("/health", (c) => c.json({ ok: true }));

export default app;
```

Для кінцевих точок із підтримкою бази даних тримайте запити Drizzle позаду лише серверних помічників і відкрийте їх за допомогою процедур tRPC або маршрутів Hono.

## Примітки щодо сумісності

Сумісність Astro API залежить від вибраної інтеграції інтерфейсу користувача. Ця сторінка використовує `--astro-integration react`, який утримує tRPC доступним. Для інтеграцій не-React Astro віддайте перевагу oRPC.

DaisyUI вибрано як бібліотеку інтерфейсу користувача в цій команді. Якщо ви пізніше перейдете на shadcn/ui, переконайтеся, що інтеграція Astro React та налаштування Tailwind все ще відповідають бібліотеці компонентів, яку ви вибрали.

## Коли його вибрати

Виберіть Astro, якщо вміст, документи, маркетингові сторінки або часткова гідратація є центральними для програми, але вам все одно потрібна згенерована серверна частина та налаштування бази даних.

## Примітки до розгортання

Плануйте, щоб інтерфейс Astro і Hono API мали чітко налаштовані джерела. Інтерфейсу потрібна публічна URL-адреса API. Службі Hono потрібна база даних і секрети авторизації. SQLite може підійти для локальної розробки, але робочий хостинг повинен забезпечувати постійне зберігання, якщо ви зберігаєте SQLite.

Якщо інтерфейс і API розгорнуті окремо, налаштуйте CORS і автентичні файли cookie для кінцевих доменів, а не покладайтеся на поведінку локального хоста.

## Усунення несправностей

- Якщо острівці React не гідратуються, перевірте клієнтську директиву Astro і чи безпечно імпортує компонент лише код браузера.
- Якщо tRPC недоступний після зміни інтеграції, підтвердьте, що інтеграція Astro все ще React.
- Якщо виклики API не вдаються з розгорнутих сторінок, перевірте загальнодоступне походження API та налаштування CORS.
- Якщо дані SQLite зникають після розгортання, переконайтеся, що ваша платформа хостингу підтримує постійне сховище з можливістю запису.

## Порівняльні нотатки

Виберіть це, якщо сторінки вмісту та вибіркова інтерактивність важливіші, ніж повна оболонка програми React. Виберіть [Hono з tRPC і Drizzle](/guides/typescript/hono-trpc-drizzle/), якщо інтерфейс має бути спеціальною програмою TanStack Router React.
