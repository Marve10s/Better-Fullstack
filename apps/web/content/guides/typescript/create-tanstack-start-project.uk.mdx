Використовуйте цей стек, якщо вам потрібна повна стекова програма React, створена на основі моделі маршруту сервера TanStack Router і TanStack Start.

```npm
npm create better-fullstack@latest my-tanstack-app -- \
  --ecosystem typescript \
  --frontend tanstack-start \
  --backend self \
  --database sqlite \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --css-framework tailwind \
  --ui-library shadcn-ui \
```

## Що це створює

- Веб-програма TanStack Start з маршрутами на основі файлів.
- Повна стекова маршрутизація через вбудований серверний рівень фреймворку.
- SQLite і Drizzle для налаштування невеликої локальної реляційної бази даних.
- Better Auth підключено до створеної програми.
- Tailwind CSS і shadcn/ui для інтерфейсу.
- Відтворювана конфігурація стека в `bts.jsonc`.

## Згенерована форма

Створений проект має бути єдиним розгортаним веб-додатком замість розділеного зовнішнього інтерфейсу/API робочої області. TanStack Start володіє маршрутизацією, функціями сервера та обробкою запитів, тоді як Drizzle володіє схемою бази даних і запитами.

Представницька форма:

```txt
my-tanstack-app/
  bts.jsonc
  package.json
  src/
    routes/
    components/
    lib/
      auth/
      db/
      trpc/
```

Точні назви файлів можуть змінюватися в міру розвитку генератора, але важливою межею є стабільність: код маршруту залишається в додатку TanStack Start, код бази даних залишається в помічниках Drizzle, а процедури API доступні через вибраний рівень `--api trpc`.

## Приклад маршруту та шаблону API

Типовий маршрут зберігає стан інтерфейсу користувача в React і викликає введений помічник API замість того, щоб вручну створювати URL-адреси отримання:

```tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/dashboard")({
  component: DashboardPage,
});

function DashboardPage() {
  return (
    <main className="mx-auto max-w-5xl p-6">
      <h1 className="text-2xl font-semibold">Dashboard</h1>
      <p className="text-muted-foreground">
        Load account data through the generated server API layer.
      </p>
    </main>
  );
}
```

Для нової роботи API додайте вузькі процедури навколо варіантів використання, а не негайно показуйте CRUD у формі таблиці:

```ts
import { z } from "zod";

export const projectInput = z.object({
  name: z.string().min(2),
});

export async function createProject(input: z.infer<typeof projectInput>) {
  const values = projectInput.parse(input);

  return {
    id: crypto.randomUUID(),
    name: values.name,
  };
}
```

## Приклад моделі бази даних

Drizzle найкраще працює, коли визначення схеми невеликі та чіткі. Типова таблиця SQLite може виглядати так:

```ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const project = sqliteTable("project", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  ownerId: text("owner_id").notNull(),
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
});
```

Тримайте таблиці авторизації окремо від таблиць продуктів. Better Auth може генерувати або очікувати власну схему залежно від вибраного адаптера; моделі продуктів повинні посилатися на ідентифікатор користувача, а не дублювати стан авторизації.

## Коли його вибрати

Виберіть TanStack Start, якщо вам потрібен React, типізована маршрутизація, повний стек і менша площа фреймворка, ніж у великому фреймворку з акумуляторами.

Це добре підходить для інформаційних панелей, внутрішніх інструментів, прототипів SaaS і програм, де безпека типу маршруту має значення.

## Примітки до розгортання

Перед розгортанням переконайтеся, що для бази даних визначено змінні робочого середовища, секретні значення Better Auth та URL-адресу публічної програми, яка використовується зворотними викликами авторизації. Для розгортання SQLite переконайтеся, що ваш хост підтримує постійне сховище для запису; багато безсерверних платформ цього не роблять.

Якщо ви націлюєтеся на безсерверну платформу, PostgreSQL зазвичай є безпечнішим вибором робочої бази даних, ніж локальний файл SQLite. Зберігайте `bts.jsonc`, щоб майбутні товариші по команді та агенти могли реконструювати запланований стек.

## Усунення несправностей

- Якщо зворотні виклики автентифікації переспрямовують на неправильний хост, спочатку перевірте базову URL-адресу програми та змінні середовища Better Auth.
- Якщо запити до бази даних працюють локально, але не вдаються після розгортання, перевірте URL-адресу робочої бази даних і чи проводилися міграції для розгорнутої бази даних.
- Якщо згенеровані типи маршрутів виглядають застарілими, перезапустіть процес генерації типу фреймворку та повторно запустіть найменшу відповідну перевірку типів.
- Якщо клієнтські виклики tRPC не вдаються через помилку 404, підтвердьте, що згенерований маршрут API все ще змонтовано там, де його очікує клієнт.

## Компроміси

TanStack Start краще підходить, якщо ви хочете долучитися до екосистеми TanStack. Якщо вам потрібна найбільша екосистема хостингу та документації, порівняйте її з [Next.js з Drizzle і Better Auth](/guides/typescript/nextjs-drizzle-better-auth/).

Порівняно з окремим бекендом Hono, цей стек має менше служб, які можна розгортати, і налаштувань між джерелами. Порівняно з Next.js, це дає вам TanStack Router-першу розумову модель і менший слід рамки, але молодшу екосистему.
