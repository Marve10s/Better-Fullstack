Використовуйте цей стек, якщо вам потрібна основна React повноцінна програма з реляційними даними, автентифікацією та типізованим рівнем API.

```npm
npm create better-fullstack@latest my-next-app -- \
  --ecosystem typescript \
  --frontend next \
  --backend self \
  --database postgres \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --css-framework tailwind \
  --ui-library shadcn-ui \
```

## Що це створює

- Додаток Next.js у повному режимі.
- PostgreSQL як реляційна база даних.
- Drizzle як TypeScript ORM.
- Better Auth для автентифікації.
- tRPC для наскрізних APIs.
- Tailwind CSS і shadcn/ui для стилю інтерфейсу.

## Згенерована форма

Створена програма використовує Next.js як межу Інтернету та сервера. PostgreSQL і Drizzle знаходяться позаду серверних модулів, тоді як tRPC забезпечує типізовані виклики для клієнтських компонентів, яким потрібні дані програми.

Представницька форма:

```txt
my-next-app/
  bts.jsonc
  app/
  components/
  lib/
    auth/
    db/
    trpc/
```

Точні шляхи можуть відрізнятися залежно від версії генератора, але передбачуваний розподіл є послідовним: компоненти інтерфейсу користувача відтворюють роботу з продуктом, обробники маршрутів і код сервера мають власні межі запитів, а доступ до бази даних залишається поза пакетами браузера.

## Приклад моделі Drizzle

Зберігайте таблиці продуктів зрозумілими та легкими для перенесення:

```ts
import { pgTable, text, timestamp } from "drizzle-orm/pg-core";

export const workspace = pgTable("workspace", {
  id: text("id").primaryKey(),
  name: text("name").notNull(),
  ownerId: text("owner_id").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

Better Auth має володіти таблицями автентифікації та поведінкою сеансу. Таблиці продуктів мають посилатися на ідентифікатори користувачів і уникати копіювання полів сеансу в моделі додатків.

## Приклад набраної процедури

Використовуйте tRPC для операцій, де інтерфейс отримує переваги від передбачуваних типів введення та виведення:

```ts
import { z } from "zod";

export const createWorkspaceInput = z.object({
  name: z.string().min(2).max(80),
});

export async function createWorkspace(rawInput: unknown, userId: string) {
  const input = createWorkspaceInput.parse(rawInput);

  return {
    id: crypto.randomUUID(),
    name: input.name,
    ownerId: userId,
  };
}
```

Тримайте перевірку авторизації поблизу мутації. Операція створення робочої області має підтвердити, що користувач увійшов у систему, перш ніж щось вставляти.

## Коли його вибрати

Виберіть це для програм SaaS, продуктів на основі облікових записів, інформаційних панелей, порталів адміністратора та проектів, де важливе знайомство з хостингом Next.js.

## Чому Drizzle і Better Auth

Drizzle зберігає доступ до бази даних близьким до TypeScript. Better Auth надає програмі сучасний рівень автентифікації без примусового розміщення постачальника ідентифікаційної інформації за замовчуванням.

## Примітки щодо сумісності

- `--backend self` означає, що Next.js володіє межею сервера; не додавайте окрему серверну частину, якщо ви не бажаєте чітко розділити службу.
- `--database postgres` добре поєднується з робочим хостингом, об’єднаними з’єднаннями та постачальниками керованих баз даних.
- `--api trpc` добре підходить для цього стеку на основі React. Не-React TypeScript інтерфейси в Better Fullstack зазвичай використовують oRPC.
- shadcn/ui очікує Tailwind та React. Зберігайте ці варіанти узгодженими, якщо пізніше ви відновлюватимете чи додасте компоненти.

## Примітки до розгортання

Установіть рядок підключення PostgreSQL, секрети Better Auth та базову URL-адресу програми в середовищі розгортання. Виконуйте міграції, перш ніж надсилати робочий трафік до нового коду, який очікує нових стовпців або таблиць.

На безсерверному хостингу перевірте рекомендації постачальника баз даних щодо пулу. Прямі з’єднання PostgreSQL можуть швидко вичерпати обмеження, коли багато екземплярів без сервера запускаються одночасно.

## Усунення несправностей

- Якщо автентифікація працює локально, але не в робочій версії, перевірте URL-адреси зворотного виклику, надійні джерела, файли cookie та URL-адресу робочої програми.
- Якщо міграція виконується, але програма все ще бачить старі помилки схеми, підтвердьте програму та команду міграції в одній базі даних.
- Якщо клієнтські компоненти імпортують модулі бази даних лише для сервера, перемістіть запит позаду обробника маршруту, дії сервера або введеної процедури API.
- Якщо типи tRPC не оновлюються, перезапустіть сервер TypeScript і повторно запустіть перевірку типу цільової програми.
