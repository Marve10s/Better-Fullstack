Використовуйте цей стек, якщо вам потрібен швидкий сервер TypeScript API та окремий інтерфейс React із типовими викликами клієнт-сервер.

```npm
npm create better-fullstack@latest my-hono-app -- \
  --ecosystem typescript \
  --frontend tanstack-router \
  --backend hono \
  --runtime bun \
  --database postgres \
  --orm drizzle \
  --auth better-auth \
  --api trpc \
  --css-framework tailwind \
  --ui-library shadcn-ui \
```

## Що це створює

- Інтерфейс TanStack Router.
- Сервер Hono працює на Bun.
- PostgreSQL і Drizzle.
- Better Auth.
- tRPC між веб-програмою та API.
- Структура монорепо для зовнішніх і серверних пакетів.

## Згенерована форма

Ця команда створює форму розділеної програми: інтерфейс і сервер є окремими пакетами, але вони генеруються разом і мають однакову конфігурацію стека. Це робить межу API явною, не відмовляючись від висновку TypeScript.

Представницька форма:

```txt
my-hono-app/
  bts.jsonc
  apps/
    web/
    server/
  packages/
    shared/
```

Точні назви робочих областей можуть відрізнятися, але архітектурна точка однакова: TanStack Router володіє програмою браузера, Hono володіє HTTP, Drizzle володіє доступом до бази даних, а tRPC є типовим контрактом між ними.

## Приклад маршруту Hono

Hono корисний, коли обробка запитів має залишатися чіткою та легкою:

```ts
import { Hono } from "hono";

const app = new Hono();

app.get("/health", (c) => {
  return c.json({ ok: true });
});

export default app;
```

Зберігайте проміжне програмне забезпечення рівня фреймворку, контекст автентифікації та журналювання запитів у пакеті сервера. Уникайте витоку об’єктів запиту Hono у спільну бізнес-логіку.

## Приклад форми процедури tRPC

Процедури tRPC мають бути невеликими перевіреними точками входу навколо серверних операцій:

```ts
import { z } from "zod";

const createTaskInput = z.object({
  title: z.string().min(1),
});

export const taskProcedures = {
  create: async (rawInput: unknown, userId: string) => {
    const input = createTaskInput.parse(rawInput);

    return {
      id: crypto.randomUUID(),
      title: input.title,
      ownerId: userId,
    };
  },
};
```

Для великих програм розміщуйте схеми перевірки в спільному модулі лише тоді, коли вони потрібні і клієнту, і серверу. Записи в базу даних мають залишатися лише на сервері.

## Коли його вибрати

Виберіть Hono, коли серверна частина має залишатися маленькою, швидкою та чіткою. Це налаштування добре працює для API-перших продуктів, інформаційних панелей, внутрішніх інструментів і служб, які згодом можуть розділити розгортання інтерфейсу та серверу.

## Примітки щодо сумісності

- `--frontend tanstack-router` плюс `--backend hono` надає окрему веб-програму React та сервер API.
- `--runtime bun` вибирає Bun для служби Hono у цьому посібнику.
- `--api trpc` підходить тут, тому що інтерфейс базується на React. Для посібників SvelteKit, Nuxt або SolidStart замість цього Better Fullstack використовує oRPC.
- PostgreSQL і Drizzle — це пара, орієнтована на виробництво, для цієї форми розділеної служби.

## Примітки до розгортання

Плануйте дві цілі, які можна розгортати, якщо ваш хост обробляє інтерфейс і сервер Hono окремо. Уважно налаштуйте CORS, домени файлів cookie автентифікації та загальнодоступні URL-адреси API; розділені служби роблять ці деталі видимими.

Серверу API потрібен рядок з’єднання PostgreSQL та секрети авторизації. Для веб-програми потрібне джерело API та будь-які загальнодоступні значення URL-адреси програми. Зберігайте секрети від загальнодоступних змінних під час збірки інтерфейсу.

## Усунення несправностей

- Якщо запити браузера не виконуються до досягнення Hono, перевірте CORS і налаштовану базову URL-адресу API.
- Якщо в доменах відсутні автентифікаційні файли cookie, перевірте налаштування одного сайту, безпечні файли cookie та чи відповідають домени web/API запланованому розгортанню.
- Якщо tRPC викликає компіляцію, але не вдається під час виконання, переконайтеся, що адаптер Hono tRPC змонтовано за тим самим шляхом, який використовується клієнтом.
- Якщо згенеровані програми не можуть підключитися до PostgreSQL локально, переконайтеся, що база даних запущена та рядок підключення відповідає вибраній базі даних.
