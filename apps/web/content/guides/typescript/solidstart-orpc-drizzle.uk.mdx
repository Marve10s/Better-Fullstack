Використовуйте цей стек, якщо вам потрібна детальна реактивність Solid із фреймворком повного стека та введеними контрактами API.

```npm
npm create better-fullstack@latest my-solidstart-app -- \
  --ecosystem typescript \
  --frontend solid-start \
  --backend self \
  --database sqlite \
  --orm drizzle \
  --auth better-auth \
  --api orpc \
  --css-framework tailwind \
```

## Що це створює

- Додаток SolidStart із повним стеком.
- SQLite і Drizzle.
- Better Auth.
- oRPC для типізованих контрактів.
- Tailwind CSS.

## Згенерована форма

Цей стек зберігає SolidStart як фреймворк повного стеку. Додаток може відтворювати Solid UI, викликати введені серверні контракти та зберігати дані через Drizzle без запровадження окремої серверної служби.

Представницька форма:

```txt
my-solidstart-app/
  bts.jsonc
  src/
    routes/
    components/
    lib/
      auth/
      db/
      rpc/
```

Використовуйте це дерево як карту власності. Код інтерфейсу користувача належить до компонентів і маршрутів Solid; база даних і код авторизації повинні залишатися лише серверними.

## Приклад компонента маршруту

Маршрути SolidStart можуть залишатися зосередженими на візуалізації, поки код сервера обробляє доступ до даних:

```tsx
export default function ProjectsPage() {
  return (
    <main class="mx-auto max-w-4xl p-6">
      <h1 class="text-2xl font-semibold">Projects</h1>
      <p class="text-gray-600">Create typed server calls for project data.</p>
    </main>
  );
}
```

Зберігайте мутації сервера за підтвердженими функціями, щоб інтерфейс користувача не став єдиним джерелом правди для правил введення.

## Приклад моделі Drizzle

SQLite є практичним типовим варіантом для невеликих програм SolidStart і локальної розробки:

```ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const note = sqliteTable("note", {
  id: text("id").primaryKey(),
  body: text("body").notNull(),
  ownerId: text("owner_id").notNull(),
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
});
```

Перейдіть до PostgreSQL, коли кілька розгорнутих екземплярів потребують спільного використання надійних реляційних даних.

## Примітки щодо сумісності

SolidStart використовує oRPC в Better Fullstack. tRPC орієнтований на React, тому цей стек навмисно зберігає `--api orpc`.

`--backend self` означає, що SolidStart володіє рівнем сервера. Не додавайте Hono, якщо ви навмисно не бажаєте окремого розгортання API.

## Коли його вибрати

Виберіть SolidStart, якщо вам потрібна модель середовища виконання Solid, але все ще потрібен згенерований повний проект із базою даних, автентифікацією та введеним API підключенням.

## Примітки до розгортання

Установіть секрети Better Auth, URL-адресу програми та шлях до бази даних або рядок підключення для цільового середовища. Якщо ваша платформа розгортання не надає постійного диска, не покладайтеся на файлову підтримку SQLite для робочих даних.

Для невеликих внутрішніх інструментів може бути достатньо SQLite. Для багатокористувацьких робочих додатків у стилі SaaS PostgreSQL зазвичай легше працювати в різних розгортаннях.

## Усунення несправностей

- Якщо виклики oRPC не вдаються після розгортання, перевірте базовий шлях маршруту та чи адаптер розгортання обробляє серверні маршрути належним чином.
- Якщо сеанси автентифікації зникають, перегляньте налаштування безпеки файлів cookie та значення URL-адреси програми.
- Якщо дані SQLite скидаються, перевірте, чи хост забезпечує постійне зберігання.
- Якщо компоненти Solid випадково імпортують модулі сервера, перемістіть виклик позаду функції сервера або контракту API.
