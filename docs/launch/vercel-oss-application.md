## One-sentence description

Better Fullstack is an open-source visual builder and CLI that turns stack choices into preconfigured, compatibility-aware fullstack starters across eight language ecosystems.

## Project narrative

Starting a fullstack project usually means repeating the same integration work before product development begins: choosing compatible frameworks, wiring database and authentication layers, configuring package boundaries, and translating the result into a reproducible setup.

Better Fullstack makes that setup an explicit, typed stack plan. Developers can configure a project visually, run the same plan through the CLI, or give a coding agent structured access through the MCP server. The project currently spans TypeScript, React Native, Rust, Python, Go, Java, Elixir, and .NET, with hundreds of configurable tools covering frontend, backend, data, auth, payments, AI, quality, and deployment.

The project does not claim that every theoretical combination is verified. Compatibility rules filter known-invalid choices, and a growing set of reference stacks is exercised through end-to-end generation and validation gates. The same schema is shared by the web builder, CLI, preview system, and MCP server, which keeps generated commands reproducible across interfaces.

## Community contribution

Better Fullstack lowers the cost of trying open-source frameworks together. It gives maintainers reproducible integration examples, gives developers a compatibility-aware starting point, and gives coding agents typed tools instead of relying on remembered flags or hand-written boilerplate. The project accepts contributions under a public Code of Conduct and documents its generator validation methodology.

## Relationship to Vercel

The public website and visual builder are hosted on Vercel. Better Fullstack can scaffold Vercel deployment configuration for supported web and server stacks and includes Vercel ecosystem tools such as Next.js and the AI SDK. The press kit and generated reference stacks make it possible to publish reproducible Vercel deployment examples rather than static screenshots.
