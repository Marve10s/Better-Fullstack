# Projects

Project documents contain unfinished work only. Folder placement distinguishes active work from
conditional backlog. Completed and superseded plans belong in Git history.

The canonical product direction and priority order live in `docs/next-updates-roadmap.md`. Project
documents explain execution, but they do not override the roadmap or
the executable source.

## Active

- `active/non-social-growth.md` - [Growth and distribution](../next-updates-roadmap.md#growth-and-distribution): measurement baseline, external listings, and article deployment checks
- `active/platform-features.md` - [Phase 1](../next-updates-roadmap.md#phase-1-establish-a-real-supported-update-window): supported-window activation using published qualification evidence
- `active/documentation-follow-ups.md` - [Phase 0](../next-updates-roadmap.md#phase-0-make-every-claim-reproducible): compatibility references and localization completion

## Backlog

These requests remain conditional on demand and a maintained verification recipe. They are not
scheduled commitments; priority comes from the roadmap.

- `backlog/integrations.md` - capability depth, candidate additions, and unresolved integration decisions

## Maintenance

Keep library and ecosystem requests in the shared backlog. Create a separate active plan only
when approved work needs design decisions or coordination across implementation steps. When work
finishes, remove its backlog row, update the roadmap, retain durable rules in `docs/guidelines/`,
and delete any temporary project plan.
Git history retains completed plans; do not maintain a second archive in the working tree.
